# Встроенный терминал

Настоящий PTY (xterm + node-pty), а не запускалка команд. Ваш шелл, ваш промпт,
ваши алиасы.

![Встроенный терминал](../../screenshots/terminal.webp)

- **Несколько вкладок на репозиторий**, каждая стартует в папке этого
  репозитория.
- Стыкуйте его **под** графом или **колонкой справа**; панель запоминает свой
  размер.
- Видимость терминала своя у каждого репозитория: переключение на вкладку, где
  его ни разу не открывали, оставит его закрытым.
- Вкладки называют себя по тому, что в них выполняется.
- Свёрнутый список терминалов ужимается в **рейку**: по иконке на терминал (у
  разделённых терминалов — мини-карта панелей), клик переключает, правый клик даёт
  привычное меню переименования/разделения/убийства.
- **Перетащите один терминал на другой** в списке, чтобы объединить их в
  разделённую группу. Каждый терминал сохраняет своё имя как панель; группа
  получает новое нумерованное имя.

![Две панели, разделённые бок о бок в одной группе терминалов](../../screenshots/terminal-split.webp)

## Клавиши

| Клавиши | Действие |
|---|---|
| <kbd>⌃`</kbd> | Показать или скрыть терминал — физическая клавиша Control, на любой платформе |
| <kbd>⌘T</kbd> / <kbd>Ctrl+T</kbd> | Новый терминал, пока фокус в терминале |
| <kbd>⌘W</kbd> / <kbd>Ctrl+W</kbd> | Закрыть активный терминал; закрытие последнего скрывает панель |
| <kbd>Ctrl+Shift+C</kbd> | Копировать выделение; обычный <kbd>Ctrl+C</kbd> тоже копирует, пока есть выделение, а без него остаётся SIGINT |
| <kbd>Ctrl+V</kbd> / <kbd>Ctrl+Shift+V</kbd> / <kbd>Shift+Ins</kbd> | Вставить из буфера обмена |
| Правый клик | Копирует выделение или вставляет, если ничего не выделено |

Первые две намеренно работают только в терминале: вне его они по-прежнему
открывают и закрывают [вкладки рабочего пространства](workspaces.md). В macOS
«Копировать» и «Вставить» из меню «Правка» работают так же.

## Подсказки скриптов

Наберите `npm run ` (или `pnpm`, `yarn`, `bun run`) — и у курсора появится
список скриптов проекта, который фильтруется по мере ввода: `npm run loc` находит
`LOCAL_SERVER`. Рядом с каждым именем — команда, которую он запускает.

| Клавиша | Действие |
|---------|----------|
| **Tab** | Дополняет выбранный скрипт |
| **↑ / ↓** | Выбрать другой |
| **Esc** | Закрывает список до следующего ввода |

У других команд свой список:

| Набрано | Показывает | Откуда |
|-------|----------|------|
| `composer run ` | Скрипты Composer | ближайший `composer.json` |
| `make ` | Цели Makefile, с `## текстом` после цели как описанием | `Makefile` текущего каталога, как его читает `make` |
| `git checkout `, `switch`, `merge`, `rebase` | Локальные ветки, затем удалённые по короткому имени | репозиторий, в котором находится оболочка |

Цель Makefile, собранная из переменных или шаблона (`%.o`), не показывается, а
`git checkout -b` списка не получает: он задаёт имя новой ветке.

Скрипты берутся из `package.json`, ближайшего к **текущему** каталогу оболочки,
так что после `cd frontend` вы видите скрипты фронтенда. Сначала идут имена,
начинающиеся с набранного, затем — содержащие его.

Список знает только клавиши, набранные после последнего Enter. Вызов команды
стрелкой ↑, перемещение курсора или собственное Tab-дополнение оболочки меняют
строку вне его поля зрения, поэтому он молчит до следующего Enter, а не дополняет
не то. В Windows текущий каталог прочитать нельзя, так что список следует за
папкой, в которой открыт терминал.

## Ваш PATH

Оболочка запускается как **login shell**, так же как в Terminal.app или iTerm,
поэтому `~/.zprofile`, `~/.zlogin` и `~/.bash_profile` выполняются. Это важно:
менеджеры версий и `brew shellenv` обычно прописываются именно там — инструмент
вроде `fvm`, `nvm` или `pyenv`, работающий в вашем терминале, работает и здесь.

Ещё Gitcito при запуске спрашивает у вашей login shell её настоящий `PATH` и
подмешивает его во всё, что запускает, потому что GUI-приложение, открытое из
Dock, почти ничего не наследует. Если команда всё равно не находится, проверьте,
что она в `PATH` именно login shell, а не только интерактивной.

Всё, что вы запускаете здесь, невидимо для собственных блокировок Gitcito, так
что долгий `git rebase`, набранный руками, и клик в интерфейсе всё ещё могут
столкнуться — приложение перечитывает состояние с диска, когда терминал
что-то меняет.

## Оболочка, тема и Oh My Posh

В Windows раздел Настройки → Макет выбирает оболочку, которую запускает каждый
новый терминал, — PowerShell, PowerShell Core (`pwsh`), `cmd`, Git Bash, WSL или
свой исполняемый файл. Внешний вид терминала (тема, размер и семейство шрифта)
находится в Настройки → Темы → Тема терминала и сразу применяется ко всем
сеансам.

Если установлен [Oh My Posh](https://ohmyposh.dev), раздел также показывает
каждый `*.omp.json` из `%POSH_THEMES_PATH%` с живым предпросмотром — выбранная
тема передаётся новым терминалам как `POSH_THEME`, поэтому обычный
`oh-my-posh init pwsh` в вашем профиле её подхватит. Работает и свой путь к
`.omp.json`; если оставить поле «По умолчанию», сохранится то, что уже задают
оболочка/профиль или глобальный `POSH_THEME`. Открытые сеансы сохраняют свою тему
— закройте и снова откройте терминал, чтобы применить новую. Для глифов
приглашения нужен Nerd Font в семействе шрифта терминала (например,
`CaskaydiaMono Nerd Font`), иначе значки будут квадратиками.

О скорости: Oh My Posh запускает свою программу при каждом приглашении — около
100–200 мс в Windows, дольше для тем с git-сегментом в большом репозитории, — и
это ощущается как короткая пауза перед каждым приглашением, а не как задержка
Gitcito. Темы без git-сегмента работают быстрее всего. Важен и стиль подсказок
PowerShell: `-PredictionViewStyle InlineView` перерисовывает небольшую область
при каждом нажатии, а `ListView` — целый блок.
