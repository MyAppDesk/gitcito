# 워크트리와 서브모듈

## 워크트리

워크트리는 같은 저장소를 자기만의 폴더에 두 번째로 체크아웃한 것이에요. 그래서
`feature/x`를 떠날 때 그대로 둔 채로 `main`을 들여다볼 수 있어요. 스태시할 필요
없이요.

- 사이드바에서 워크트리를 만들고 지울 수 있어요. **더블클릭**하면 그 워크트리가
  자기 탭으로 열리고, 오른쪽 클릭에는 *워크트리 열기*, *폴더에서 보기*, 제거가
  있어요.
- 로컬 브랜치를 오른쪽 클릭 → **워크트리로 열기**를 하면 형제 폴더에 하나를 만들어
  탭으로 열어 줘요.
- 브랜치는 한 번에 워크트리 하나에만 있을 수 있어서, 다른 워크트리가 이미 들고 있는
  브랜치를 체크아웃하는 건 성공할 수 없어요 — git이 *already used by worktree at …*
  라며 거절하죠. Gitcito는 대신 그곳으로 데려가요. 브랜치 메뉴에 *`x`가 있는
  워크트리로 이동*이 보이고, 행을 더블클릭하면 실패하는 대신 그 워크트리 탭이
  열려요.

### 워크트리 관리

지난달에 만든 워크트리는 잊기 쉽고, 질문은 정리할 때 생깁니다. 작업이 남아 있나? 그 폴더가 아직 있나? 각 행이 묻기 전에 답해 줍니다.

| 행 표시 | 의미 |
|---|---|
| **●3** | 해당 워크트리에 커밋되지 않은 변경이 있는 파일 3개 |
| **↑2 ↓1** | 브랜치가 upstream보다 커밋 2개 앞서고 1개 뒤처짐 |
| 🔒 | 잠김 — 마우스를 올리면 잠글 때 적은 이유가 보입니다 |
| **없음**, 이름에 취소선 | 폴더가 사라졌고 git에는 기록만 남아 있습니다 |

숫자는 섹션을 열 때, 해당 워크트리의 커밋이 바뀔 때, 창이 포커스를 되찾을 때 읽습니다. 새로 고칠 때마다 읽지 않는 이유는 각각이 다른 폴더 안에서 실행하는 `git status`이기 때문입니다.

행을 오른쪽 클릭하면:

| 작업 | 하는 일 |
|---|---|
| **워크트리 잠금** | git(및 다른 클라이언트)이 정리·이동·제거하지 못하게 합니다. 이유(*외장 드라이브에 있음* 등)를 적으면 자물쇠에 표시됩니다. 항상 연결되어 있지 않은 매체의 워크트리에 사용합니다. |
| **워크트리 잠금 해제** | 그 반대입니다. 실행 취소하면 같은 이유로 다시 잠깁니다. |
| **워크트리 이동…** | 폴더를 옮기고 git 연결을 양쪽 모두 갱신합니다. 잠겨 있거나 탭에서 열려 있으면 사용할 수 없습니다. 탭과 레이아웃은 경로로 기억되므로 탭이 아무것도 가리키지 않게 되기 때문입니다. 먼저 탭을 닫으세요. 실행 취소하면 원래 위치로 돌아갑니다. |
| **워크트리 제거** | 먼저 무엇을 잃게 되는지 git에 확인합니다. 깨끗한 워크트리는 일반 확인을 받고, 실행 취소하면 같은 브랜치·같은 폴더로 다시 만들어집니다. 커밋되지 않은 변경이 있으면 파일 수를 알려 주는 별도 확인 *버리고 제거*가 나오며 실행 취소할 수 없습니다. |
| **이동한 폴더 다시 연결…** | *없음* 행에서만 가능합니다. 폴더가 옮겨 간 곳(파일 관리자로 옮긴 곳)을 지정하면 git이 `git worktree repair`로 다시 연결합니다. |
| **없는 워크트리 정리** | 없는 행이 있을 때 섹션 머리글에 나타나는 지우개 버튼도 같은 기능입니다. `git worktree prune`을 실행합니다. |

이 작업들이 **하지 않는** 것:

- **워크트리를 제거하면 무시된 파일도 삭제됩니다** — `.env`, `node_modules`, 빌드 출력. git은 이를 변경으로 세지 않으므로 "깨끗한" 확인에서도 알려 주며, 실행 취소로 복원되지 않습니다.
- **정리는 git의 기록만 지웁니다.** 지울 파일은 없습니다(폴더가 이미 없으므로). 잠긴 워크트리는 건너뜁니다. 분리된 드라이브의 잠긴 워크트리는 삭제된 것과 똑같아 보이기 때문입니다.
- 잠금은 git 클라이언트 사이의 약속이지 파일 보호가 아닙니다. git 밖의 무언가가 폴더를 지우는 것은 막지 못합니다.
- 메인 워크트리(저장소 자체)는 잠그거나 옮기거나 제거할 수 없습니다.
- 워크트리를 제거해도 브랜치는 삭제되지 않습니다. 다 썼다면 브랜치 목록에서 삭제하세요.

## 서브모듈

서브모듈을 추가하고, 업데이트(초기화 및 체크아웃)하고, URL을 동기화하고, 제거할 수
있어요. 각각의 상태도 실시간으로 함께 보여 줘요.

| 상태 | 의미 |
|---|---|
| **동기화됨** | 부모가 기록한 커밋에 체크아웃되어 있어요 |
| **수정됨** | 다른 곳에 체크아웃되어 있거나, 변경 사항이 있어요 |
| **초기화되지 않음** | 기록은 되어 있지만 한 번도 체크아웃되지 않았어요 |
