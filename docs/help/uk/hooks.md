# Хуки та .gitignore

## Хуки

Перегляньте всі хуки репозиторію, побачте, які з них справжні, а які досі
`.sample`, і вмикайте, вимикайте, редагуйте або створюйте їх.

![Менеджер хуків](../../screenshots/hooks.webp)

Gitcito розпізнає власний **`core.hooksPath`** (husky і подібні) та конфігурацію
**pre-commit framework** і попереджає, коли хуки живуть деінде, а не в
`.git/hooks`, — інакше ви редагували б файл, який git ніколи не запускає.

> Для комітів Gitcito хуки виконуються так само, як і для `git commit`. Хук, що
> завершився помилкою, блокує коміт, а його вивід повертається у тексті помилки.

## Розумний .gitignore

Клацніть правою кнопкою на файлі → **Ігнорувати** і виберіть:

| Вибір | Записує |
|---|---|
| Цей файл | `path/to/file.log` |
| Усі `*.ext` | `*.log` |
| Усю теку | `path/to/folder/` |

![Вибір правила для .gitignore](../../screenshots/gitignore-chooser.webp)

Правило потрапляє до `.gitignore` **найближчої теки** або до кореня репозиторію,
із живим попереднім переглядом рядка, перш ніж ви на нього погодитеся. Для вже
відстежуваних файлів у тому ж діалозі з’являється **Ігнорувати та припинити
відстеження**.
