# 前回から何が変わったか

あるブランチをレビューしました。誰かがそれをリベースしてフォースプッシュしました。
ふつうの差分はもう役に立ちません。リベース後のコミットはすべて新しいコミットなので、
何もかもが新規に見えるからです。

`git range-diff` は 2 つのバージョンをコミット単位で対応づけます。そして Gitcito は
古い位置を **reflog** から直接読み取ります。つまり、これが動くために事前に何かを記録
しておく必要はありませんでした。

![フォースプッシュ後の、書き換えられた・新しい・落とされたコミット](../../screenshots/range-diff.webp)

| 判定 | 意味 |
|---|---|
| **書き換え** | 同じコミットで、中身が変わったもの。展開すると interdiff が見えます — ファイル全体ではなく、メッセージの手直しと追加されたチェックだけが。 |
| **新規** | 見たあとに追加されたもの。 |
| **削除** | 見たあとに消えたもの。 |
| **変更なし** | 書き換えを無傷で生き延びたもの。 |

## たどり着き方

- **書き換えられた履歴を見つけたフェッチが、そう教えてくれます。** トーストがブランチ
  名を告げ、リモートの下のその行に **⟳** が付きます。クリックすれば、以前指していた
  コミットちょうどの位置で比較が開きます。
- 任意のブランチを右クリック → *前回から何が変わったか…*
- <kbd>⌘K</kbd> → *前回から何が変わったか*

## 以前の位置

ref の入力欄の下に並ぶチップは、そのブランチの reflog です。強制更新、リベース、
リセットが、いつ起きたのかとともに並びます。1 つ選べば、それを相手に比較がやり直され
ます。機能としてはそれだけです。ブランチがどこにいたかの履歴は、すでにあなたのディスク
の上にあります。
