# 브랜치, 원격, 사이드바

순서를 바꿀 수 있고 검색이 되는 사이드바 하나에 **브랜치, 원격, 태그, 스태시,
워크트리, 서브모듈**이 전부 들어 있어요. 모든 섹션은 숨기거나 순서를 바꿀 수 있고
(설정 → 레이아웃), 필터 상자는 그 전부에 적용돼요.
어떤 섹션과 폴더를 펼쳐 두거나 접어 두었는지는 저장소별로 기억되고, 재시작 후에도 유지돼요.

![고정 브랜치를 맨 위에 붙들어 둔 사이드바](../../screenshots/pinned-branches.webp)

## 브랜치

로컬이든 원격이든 만들고, 체크아웃하고, 이름을 바꾸고, 지울 수 있어요. 브랜치
행에는 이런 것이 표시돼요.

- 업스트림 대비 **↑앞섬 / ↓뒤처짐**,
- **원격별 존재 배지**(어느 원격에 이 브랜치가 있는지),
- [충돌 레이더](conflict-radar.md) 스캔 이후에 붙는 **위험 점**,
- 원격이 [히스토리를 재작성](range-diff.md)했을 때의 **⟳ 표시**.

이름에 `/`가 들어간 브랜치는 자동으로 접을 수 있는 폴더로 묶여요.
폴더 머리글을 우클릭하면 그룹 전체에 대해 동작해요. *`feature` 아래 모든 브랜치 삭제 (4개)*는 정확히 어떤 브랜치가 지워지는지
나열하는 한 번의 확인 뒤에 안의 것을 전부 삭제해요 — 지금 있는 브랜치는 제외돼요. 같은 메뉴가 원격 브랜치 폴더에도 있고, 그쪽은
원격에서 삭제해요.

도구 모음의 브랜치 드롭다운은 로컬과 원격 브랜치를 나열해요. 드롭다운의 브랜치를
마우스 오른쪽 버튼으로 클릭하면 로컬 브랜치 이름 바꾸기, 이름 복사, 새 워크트리에서
체크아웃, 활성 브랜치로 병합, 삭제를 할 수 있어요. 원격 브랜치에는 이름 바꾸기가
없고, 확인 후 원격에서 삭제돼요. 선택한 참조가 이미 활성 브랜치에 포함되어 있으면
Gitcito는 병합을 표시하지 않고, 해당 브랜치가 이미 체크아웃되어 있으면 워크트리
만들기를 비활성화해요.

![도구 모음 드롭다운의 로컬 브랜치 작업](../../screenshots/branch-dropdown-local-context-menu.webp)

![도구 모음 드롭다운의 원격 브랜치 작업](../../screenshots/branch-dropdown-remote-context-menu.webp)

행은 파일처럼 여러 개를 선택할 수 있어요. <kbd>⌘/Ctrl</kbd>+클릭은 행 하나를 토글하고, <kbd>Shift</kbd>+클릭은
범위를 선택하고, <kbd>Shift</kbd>+<kbd>↑</kbd>/<kbd>↓</kbd>는 마지막으로 클릭한 행에서 선택을 넓혀요. 선택
위에서 우클릭하면 일괄 메뉴 — *브랜치 4개 삭제* — 가 열리고, 전체 목록과 함께 확인해요. 같은 제스처가 원격 브랜치, 태그,
스태시에서도 동작해요.

![슬래시로 나뉜 브랜치 이름이 트리로 묶인 모습](../../screenshots/branch-grouping.webp)

## 고정 브랜치

자꾸 돌아오게 되는 브랜치에는 별을 달아 두세요. 행 위에 마우스를 올리고 ★를
누르거나, 우클릭 → *브랜치 고정*을 고르면 돼요. 고정한 브랜치는 로컬 섹션 맨 위의
**고정됨** 그룹에 나타나고, 저장소별로 기억되며, 아래쪽 원래 자리에도 그대로
남아 있어요.

## 원격 브랜치 체크아웃

원격 브랜치를 더블클릭하면 그 브랜치를 추적하는 로컬 브랜치가 만들어져요. 같은
이름의 로컬 브랜치가 이미 있고 **갈라져 있다면**, Gitcito가 어떻게 맞출지
물어봐요 — 리베이스, 머지, 리셋 중에서 고르면 되고, 먼저 브랜치를 백업해 줄지도
물어봐요.

![갈라진 브랜치 안내: 리베이스·머지·리셋과 백업 옵션](../../screenshots/diverged-checkout.webp)

### 로컬 브랜치가 뒤처져 있을 때

체크아웃과 함께 원격 끝까지 패스트포워드됩니다. 작업 트리가 지저분하면 이름이 붙은
스태시에 넣었다가 나중에 되돌리므로, 로컬 편집 때문에 업데이트가 중단되지 않습니다.

### 로컬 브랜치가 앞서 있을 때

로컬 브랜치가 앞서 있고 원격에 새 내용이 없다면, 체크아웃은 *원격* 브랜치를 요청한
동작에 아직 푸시하지 않은 내 작업으로 답하는 셈입니다. 그래서 어느 쪽을 뜻했는지
말할 때까지 아무것도 체크아웃하지 않습니다.

| 선택 | 결과 |
|------|------|
| 로컬 체크아웃 | 로컬 브랜치로 전환하고 커밋은 그대로 둡니다. 다른 클라이언트가 조용히 하는 동작입니다. |
| 리셋(soft) | 브랜치를 원격 끝으로 되돌리고, 커밋의 변경 사항은 **스테이지**에 남겨 다시 커밋할 수 있게 합니다. |
| 리셋(mixed) | 같은 이동이지만 변경 사항은 작업 트리에 **스테이지되지 않은 채** 남습니다. |
| 리셋(hard) | 커밋과 그 변경 사항을 *모두* 버립니다. |

![앞선 브랜치 대화상자: 로컬 체크아웃 또는 soft·mixed·hard 리셋](../../screenshots/ahead-checkout.webp)

*먼저 백업 브랜치 만들기*를 켜 두면 무엇이 움직이기 전에 로컬 끝이
`backup/<브랜치>-<타임스탬프>`로 저장되어, hard 리셋도 체크아웃 한 번이면 되돌릴 수
있습니다. 리셋은 실행 취소 스택(⌘Z)에도 들어가지만 저장소를 닫기 전까지만 유효하며,
백업 브랜치는 그보다 오래 남습니다.

**한계:** 이 대화상자는 방금 가져온 추적 ref와만 비교하므로, 페치를 거부한 원격
(오프라인, 잘못된 자격 증명)은 마지막으로 알려진 끝과 비교됩니다. 커밋이 *좋은지*는
말해 주지 않고, 여기에는 있고 저기에는 없다는 사실만 알려 줍니다.
