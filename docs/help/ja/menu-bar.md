# メニューバー

メニューバーは、ほかのどの画面もうまく答えられない問いに答えます。*このアプリは
そもそも何ができるのか？* [コマンドパレット](search.md)は探すものが分かっていれば
速く、[チートシート](keyboard.md)はキーを一覧にします。ただしどちらも「眺めて回る」
場所ではありません。メニューはそれができます。

メニューにあるものはすべて、ウインドウの中からも到達できます。メニューだけにある
機能は意図的に置いていません。メニューにしかない機能は、Windows と Linux の利用者
には存在しない機能だからです。

## どこに何があるか

| メニュー | 内容 |
|---|---|
| **Gitcito** | このアプリについて、アップデート確認、[設定](repo-settings.md)、標準の非表示と終了の項目 |
| **ファイル** | 新規タブ、リポジトリを開く／[クローン](cloning.md)、最近使った項目、タブを閉じる・開き直す |
| **編集** | カット、コピー、ペースト、取り消し（キーボードが元々行うテキスト編集）と[コード検索](search.md) |
| **表示** | コマンドパレット、サイドバーとパネルの切り替え、[ターミナル](terminal.md)、[mission control](mission-control.md)、[金庫](vault.md)、ズーム |
| **リポジトリ** | Fetch、pull、push、コミット、stash、新規ブランチ、[pull request](hosting.md)、取り消し、Finder に表示、リポジトリ設定 |
| **ウインドウ** | しまう、拡大／縮小、すべてを手前に移動 |
| **ヘルプ** | このハンドブック、チートシート、新機能、ライセンス、問題の報告 |

アクティブなタブが git リポジトリでないとき、リポジトリメニューは全体が淡色になり、
取り消せる操作がなければ**取り消し**が淡色になります。メニューはそのまま、「いま
このアプリが何を許すか」の読める要約になっています。

## ショートカットは表示するもので、奪うものではない

各項目の横に出るキーは、実際に割り当てられているキーです。設定で <kbd>⌘K</kbd> を
割り当て直せば、表示メニューもそう書き換わります。

これが成り立つのは、メニューがその組み合わせを*表示するだけ*で占有しないからです。
キーボードの処理は引き続き Gitcito 自身が担い、だからこそ同じショートカットが
カーソルの位置によって違う振る舞いをできます。この方法で示せない唯一のものは、
Gitcito のものではないショートカットです。<kbd>⌘F</kbd> は読んでいるファイルや差分の
ものなので、どのメニュー項目もそれを占有しません。

## 制限

- **macOS のみ。** Windows と Linux ではウインドウがフレームレスで、タイトルバーは
  Gitcito 自身が描いています。メニューバーの居場所がありません。そちらでは
  [コマンドパレット](search.md)と[キーボードショートカット](keyboard.md)から同じ
  コマンドに届きます。
- **再読み込みとデベロッパツールは開発ビルドにのみ出ます。** 再読み込みは開いている
  すべてのタブの状態を捨てます。リリース版が「拡大／縮小」の隣で差し出すものでは
  ありません。
- **最近使った項目は最大 10 個のリポジトリ**を新しい順に並べ、
  [ようこそ画面](getting-started.md)と同じ一覧をたどります。
- **閉じたタブを開き直すは淡色になりません。** 閉じたタブのスタックはセッション中
  だけ存在し、メニューからは見えません。開き直すものがない状態で選んでも何も
  起きません。
