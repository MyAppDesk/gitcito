# 作者头像

提交列表是一面名字组成的墙，而名字读起来很慢。每个名字旁边放一张图，"这是谁写的"就变成了一眼就能
回答的问题。Gitcito 会给它显示的每位作者配一张：图形视图的作者列、提交详情里作者和每位共同作者旁边、
撰写提交时的共同作者选择器、配置切换器，以及设置中每个配置的旁边。

## 图从哪里来

两个来源，按此顺序尝试：

| 来源 | 什么时候用 |
|---|---|
| **Gravatar** | 提交邮箱有 Gravatar 账号。通过 HTTPS 获取，依据邮箱小写形式的 SHA-256 哈希。 |
| **生成的头像** | 其余所有情况——没有 Gravatar、没有网络，或关闭了查询。在本地依据邮箱绘制，从不下载。 |

生成的头像是一只小生物，不是一个彩色方块：同一个邮箱永远产生同样的形状和同样的颜色，所以跨仓库、跨
重启，作者都还认得出来。两个不同邮箱基本不会撞在一起。它由
[blobatar](https://github.com/Alain00/blobatar)（MIT）绘制，完全不需要网络——一个满是没有 Gravatar
的作者的仓库，依然能在首次绘制时离线得到一整套可区分的面孔。

由于种子是**提交邮箱**，用两个地址提交的作者会得到两个头像。这是刻意的——它和图形视图作者列给出的是
同一个信号，而且通常正是这样发现机器账号或配置错误的 `user.email`。如果两个地址确实是同一个人，用
[作者属性](attributes.md)来纠正。

## 标题栏里的那张脸

配置名称旁边的头像，是 Gitcito 中唯一代表**此刻、在这个仓库里的你**的头像——所以它也是唯一会对仓库
状态作出反应的头像。它会摆出四种表情之一：

| 表情 | 什么时候 |
|---|---|
| 😠 生气 | 还有文件处于冲突状态。 |
| 🙁 沮丧 | 有 10 个或更多提交等待推送、落后远端 25 个或更多提交，或有 25 处及以上未提交的更改。 |
| 🙂 满足 | 本地没有东西、没有等待项，并且有一个可以说"已同步"的上游。 |
| 😐 平常 | 普通的进行中工作——以及第一次状态读取之前。 |

![标题栏中摆出生气表情的头像](../../screenshots/avatar-mood.webp)

最糟的那个胜出：一个既有冲突*又*有四十个未推送提交的仓库是生气，不是沮丧。把指针悬停在头像上，提示
会说明是哪个计数造成了这张脸——一张不说明缘由就变化的图是谜题，不是信号。

阈值故意设得很高。一个提交没推送就沮丧的脸，会永远沮丧下去，而长期亮着的信号就是人们学会不看的信号。
没有上游的分支保持平常而不是满足："已同步"这句话，对谁都没推送过的分支说不出口。

**这是装饰，不是仪表。** 真实计数在状态栏里，那才是该信的。这张脸只是一眼告诉你*有事发生*，而且只分
四档来说。

### 动效

标题栏的头像会自己呼吸和眨眼。到
**设置 → 主题 → 图形 → 让头像动起来**关掉它——表情仍然跟随仓库，只是不再动。当系统要求减少动效时，
动效也会自动跳过。

只有这一个头像会动。会动的头像必须画成活的 SVG 而不是缓存图片，一个尚可，而滚动的图形视图要画的几百
个就太浪费了。

## 关掉查询

**设置 → 主题 → 图形 → 显示头像。**

关掉意味着：

- 永不向 `gravatar.com` 发出任何请求——不延后发送，也不缓存后重试；
- 头像照旧出现，全部在本地生成。

所以这是一个隐私开关，不是"把图藏起来"。没有任何设置能彻底去掉头像。

## 限制

- **一次 Gravatar 查询会告诉 gravatar.com 这个邮箱被看过了。** 哈希不是秘密：任何手里有候选邮箱的人
  都能算出哈希再比对。如果一个仓库的作者名单是你不愿交给第三方的东西，打开它之前先关掉查询。
- **只支持 Gravatar。** 你上传到 GitHub、GitLab 或 Bitbucket 的头像不会读取——那需要按作者逐个发起带
  认证的托管方 API 调用，为一处装饰花的网络太多了。
- **不能覆盖。** 你无法把选定的图片钉在某位作者身上，也无法更换生成风格。头像只是邮箱的函数，别无其他。
- **Gravatar 照片没有表情。** 如果你配置的邮箱有照片，标题栏就显示照片、不显示表情——照片没法对你做鬼
  脸。如果你更想要会表达的小生物，就关掉查询。
- **表情只跟随当前仓库。** 在不是仓库的标签页里没有可反应的对象，所以它保持平常。
- **四种表情，不是仪表盘。** 没有对应"正在变基""分离的 HEAD""贮藏越积越多"的表情：四个姿态就是全部
  词汇，把它们花在更细的区分上，会让每一次解读都不可靠。
- **小就是小。** 在图形视图的作者列里头像是 16px，能传达颜色和轮廓，传达不了细节。提交详情把作者画成
  38px，那里才真的看得见脸。
