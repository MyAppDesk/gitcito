# アクセシビリティ

Gitcito は、マウスなしで操作でき、スクリーンリーダーで読めることを目指して
います。このページでは、それが具体的に何を意味するのか — そして限界がどこに
あるのか — を説明します。

## キーボード

- **タブ、サイドバーの行、ファイル一覧、ツールバーのメニュー**はフォーカス
  でき、Enter または Space で実行できます。分割ボタン（pull/push/stash）は、
  ドロップダウンの矢印を独立したフォーカス可能なコントロールとして公開します。
- **コミットグラフ**はフォーカスの停止点が 1 つです。フォーカスして上下キー
  （または j/k）で履歴をたどります。選択中のコミットは件名・作者・位置とともに
  読み上げられます。Shift+F10（またはメニューキー）で選択中のコミットの
  コンテキストメニューが開きます。
- **コンテキストメニュー**はフォーカスされた状態で開きます。矢印キーで移動、
  Enter で実行、ArrowRight/ArrowLeft でサブメニューへの出入り、Escape で
  閉じます。
- **ダイアログ**は Tab を内側に閉じ込め、閉じるときにフォーカスを元の場所へ
  返し、Escape で閉じられます。
- **コマンドパレット**（Cmd/Ctrl+K）はコンボボックスです。入力中も、矢印キー
  でたどっている間も、結果が読み上げられます。

## スクリーンリーダー

- すべてのダイアログはタイトルとともに読み上げられます。トースト — アプリの
  フィードバック手段 — はライブリージョンで、成功は控えめに読み上げられ、
  エラーは割り込みます。
- 進行状況（クローン、アップデートのダウンロード）はパーセント付きのプログレス
  バーとして公開され、処理中の状態（「フェッチ中…」）は自分から読み上げられ
  ます。
- ファイルの状態は「追加」「変更」「競合」のように音声で伝えられ、色付きの
  記号だけで示されることはありません。
- ウィンドウはランドマーク（banner、main、サイドバー、ステータスバー）で構造
  化されているので、ランドマークによるナビゲーションが機能します。

## 限界を、はっきりと

- **ターミナル**は xterm.js であり、そのスクリーンリーダー対応をそのまま受け
  継ぎます — そしてそれは弱いのです。目の見えるユーザー向けの領域として扱って
  ください。ターミナルでできる git 操作は、すべて UI の操作としても存在します。
- **Cosmos（3D の履歴）、コミットグラフのレーン、画像の diff** は本質的に
  視覚的なものです。その背後にあるデータ — コミット一覧やファイル一覧 — は
  アクセシブルですが、絵そのものはそうではありません。
- **ドラッグ&ドロップ**（インタラクティブリベースの手順の並べ替え、マージの
  ためのブランチのドラッグ）は、注記のある箇所ではポインター専用です。どの
  ドラッグ操作にもメニューかボタンの同等手段があります。
- このページの背後にある監査は macOS の VoiceOver で行いました。Windows の
  NVDA/JAWS も同等に動くはずですが、実地では確認していません — 報告は
  [issues](https://github.com/MyAppDesk/gitcito/issues) として歓迎します。

## 関連する設定

**視差効果を減らす**は OS の設定から尊重されます — アニメーションは瞬時の
切り替えになります。テーマのコントラストは
[設定 → 外観](themes.md)でテーマごとに調整できます。
