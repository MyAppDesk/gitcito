# 安全分享

换一台新机器——或者来一位新队友——通常意味着把一切重新输入一遍。安全分享把这些东西打成一个加密的 `.gitcito` 文件：Gitcito 的团队功能**没有后端**，所以这个文件*就是*传输通道。用你平时发文件的任何方式把它发出去；密码走另一条路。

![把一个仓库的设置导出为加密包](../../screenshots/secure-share.webp)

![对整个工作区做同样的导出](../../screenshots/secure-workspace.webp)

## 能装些什么

| 部分 | 内容 |
|---|---|
| **保险库** | 全局保险库里的机密（按仓库存放的保险库条目留在原地） |
| **仓库文件** | 未跟踪的配置文件和机密文件，导入时会在相同的相对路径下重新落盘 |
| **工作区结构** | 标签页布局本身——分组、颜色、顺序——仓库一律以远程 URL 引用，绝不使用你的本地路径 |
| **提交备注** | 一个仓库的 `refs/notes/commits`，导入时直接应用，不需要对任何远程有写权限 |

只有你**勾选了那个选项**，机密才会被包含进去。没勾的包里完全不含任何凭据。应用设置不随包搬运——它们在设置里有自己的纯 JSON 导出。

## 导入

导入界面会在应用任何内容**之前**，逐节展示包里有什么；仓库则会与你已有的对上号——先按远程 URL，再按文件夹——这样导入不会把整个世界重新克隆一遍。

**工作区结构**一节会用你已有的仓库重建工作区；还没有的仓库会连同它们的远程地址一起列出来，你可以先克隆好再导入一次——在这里 Gitcito 绝不会替你克隆。**提交备注**一节会预览将要落下的内容——新的、相同的、不同的，或挂在你没有的提交上的——不同的备注只有在你勾选**覆盖**时才会被替换；不会合并分叉的备注。
