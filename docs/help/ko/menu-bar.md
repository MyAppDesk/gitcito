# 메뉴 막대

메뉴 막대는 다른 어떤 화면도 잘 답하지 못하는 질문에 답합니다. *이 앱은 대체 무엇을
할 수 있는가?* [명령 팔레트](search.md)는 무엇을 찾는지 알고 있을 때 더 빠르고,
[단축키 요약](keyboard.md)은 키를 나열합니다. 하지만 둘 다 훑어보는 곳은 아닙니다.
메뉴는 그런 곳입니다.

메뉴에 있는 것은 모두 창 안에서도 닿을 수 있습니다. 메뉴에만 있는 기능은 일부러
두지 않았습니다. 메뉴에만 사는 기능은 Windows와 Linux 사용자에게는 없는
기능이니까요.

## 무엇이 어디에 있는가

| 메뉴 | 내용 |
|---|---|
| **Gitcito** | 정보, 업데이트 확인, [설정](repo-settings.md), 표준 가리기 및 종료 항목 |
| **파일** | 새 탭, 저장소 열기 또는 [클론](cloning.md), 최근 항목 열기, 탭 닫기와 다시 열기 |
| **편집** | 오려두기, 복사하기, 붙여넣기, 실행 취소 — 키보드가 이미 하는 텍스트 편집 — 그리고 [코드 검색](search.md) |
| **보기** | 명령 팔레트, 사이드바와 패널 토글, [터미널](terminal.md), [mission control](mission-control.md), [금고](vault.md), 확대/축소 |
| **저장소** | Fetch, pull, push, 커밋, stash, 새 브랜치, [pull request](hosting.md), 실행 취소, Finder에서 보기, 저장소 설정 |
| **윈도우** | 최소화, 확대/축소, 모두 앞으로 가져오기 |
| **도움말** | 이 안내서, 단축키 요약, 새로운 기능, 라이선스, 문제 보고 |

활성 탭이 git 저장소가 아니면 저장소 메뉴 전체가 흐려지고, 되돌릴 것이 없으면
**실행 취소**가 흐려집니다. 메뉴는 지금 이 앱이 무엇을 허용하는지 읽을 수 있는
요약입니다.

## 단축키는 보여줄 뿐, 빼앗지 않는다

각 항목 옆의 키는 실제로 지정된 키입니다. 설정에서 <kbd>⌘K</kbd>를 다시 지정하면
보기 메뉴도 그대로 바뀝니다.

메뉴가 그 조합을 차지하지 않고 *표시만* 하기 때문입니다. 키보드 처리는 여전히
Gitcito가 맡고, 그래서 같은 단축키가 커서 위치에 따라 다르게 동작할 수 있습니다.
이 방식으로 보여줄 수 없는 유일한 것은 Gitcito의 것이 아닌 단축키입니다.
<kbd>⌘F</kbd>는 지금 읽고 있는 파일이나 diff의 것이라, 어떤 메뉴 항목도 그것을
차지하지 않습니다.

## 한계

- **macOS 전용.** Windows와 Linux에서는 창에 테두리가 없습니다. 제목 표시줄을
  Gitcito가 직접 그리므로 메뉴 막대가 있을 자리가 없습니다. 그 플랫폼에서는
  [명령 팔레트](search.md)와 [키보드 단축키](keyboard.md)로 같은 명령에 닿습니다.
- **다시 불러오기와 개발자 도구는 개발 빌드에만 나옵니다.** 다시 불러오면 열려 있는
  모든 탭의 상태가 사라집니다. 배포 버전이 '확대/축소' 옆에 둘 만한 항목이
  아닙니다.
- **최근 항목 열기는 최대 열 개의 저장소**를 최신순으로 보여주며,
  [환영 화면](getting-started.md)과 같은 목록을 따릅니다.
- **닫은 탭 다시 열기는 절대 흐려지지 않습니다.** 닫은 탭 스택은 세션 동안만
  존재하고 메뉴는 그것을 볼 수 없습니다. 되돌릴 것이 없을 때 선택해도 아무 일도
  일어나지 않습니다.
