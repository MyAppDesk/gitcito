# 내장 터미널

명령 실행기가 아니라 진짜 PTY(xterm + node-pty)예요. 여러분의 셸, 여러분의 프롬프트,
여러분의 별칭 그대로요.

![내장 터미널](../../screenshots/terminal.webp)

- **저장소마다 여러 개의 탭**을 열 수 있고, 각각 그 저장소의 폴더에서 시작해요.
- 그래프 **아래**에 도킹하거나 **오른쪽 열**로 둘 수 있고, 패널은 자기 크기를
  기억해요.
- 터미널 표시 여부는 저장소별이에요. 한 번도 터미널을 연 적 없는 탭으로 전환하면
  닫힌 채로 있어요.
- 탭은 그 안에서 실행 중인 것의 이름을 스스로 붙여요.
- 터미널 목록을 접으면 **레일**로 줄어들어요. 터미널마다 아이콘 하나씩(분할된
  터미널은 작은 패널 배치도를 보여 줘요), 클릭하면 전환하고, 오른쪽 클릭하면 평소의
  이름 바꾸기/분할/종료 메뉴가 나와요.
- 목록에서 **터미널을 다른 터미널 위로 드래그**하면 분할 그룹으로 합쳐집니다.
  각 터미널은 창으로서 자기 이름을 유지하고, 합쳐진 그룹은 새 번호 이름을
  받습니다.

![한 터미널 그룹 안에서 두 패널이 나란히 분할된 모습](../../screenshots/terminal-split.webp)

## 키

| 키 | 동작 |
|---|---|
| <kbd>⌃`</kbd> | 터미널 표시/숨기기 — 모든 플랫폼에서 물리적인 Control 키 |
| <kbd>⌘T</kbd> / <kbd>Ctrl+T</kbd> | 터미널에 포커스가 있을 때 새 터미널 |
| <kbd>⌘W</kbd> / <kbd>Ctrl+W</kbd> | 포커스된 터미널 닫기. 마지막 터미널을 닫으면 패널이 숨겨짐 |
| <kbd>Ctrl+Shift+C</kbd> | 선택 영역 복사. 선택이 있는 동안에는 단독 <kbd>Ctrl+C</kbd>도 복사하고, 없으면 SIGINT로 남음 |
| <kbd>Ctrl+V</kbd> / <kbd>Ctrl+Shift+V</kbd> / <kbd>Shift+Ins</kbd> | 클립보드에서 붙여넣기 |
| 오른쪽 클릭 | 선택 영역 복사, 선택이 없으면 붙여넣기 |

처음 두 키는 의도적으로 터미널 안에서만 동작합니다. 터미널 밖에서는 여전히
[작업 공간 탭](workspaces.md)을 열고 닫습니다. macOS에서는 편집 메뉴의 복사/붙여넣기도
같은 방식으로 동작합니다.

## 스크립트 제안

`npm run `(또는 `pnpm`, `yarn`, `bun run`)을 입력하면 커서 위치에 프로젝트의 스크립트
목록이 나타나고, 입력할수록 걸러집니다. `npm run loc`은 `LOCAL_SERVER`를 찾습니다. 각
이름 옆에는 실행되는 명령이 표시됩니다.

| 키 | 동작 |
|----|------|
| **Tab** | 선택한 스크립트 완성 |
| **↑ / ↓** | 다른 항목 선택 |
| **Esc** | 다시 입력할 때까지 목록 닫기 |

다른 명령에도 각자의 목록이 있습니다:

| 입력 | 목록 | 읽는 곳 |
|---|---|----|
| `composer run ` | Composer 스크립트 | 가장 가까운 `composer.json` |
| `make ` | Makefile 타깃, 타깃 뒤의 `## 텍스트`를 설명으로 | 현재 디렉터리의 `Makefile`(`make`가 읽는 방식대로) |
| `git checkout `, `switch`, `merge`, `rebase` | 로컬 브랜치, 그다음 원격 브랜치를 짧은 이름으로 | 셸이 있는 저장소 |

변수나 패턴(`%.o`)으로 만든 Makefile 타깃은 나오지 않으며,
`git checkout -b`에는 목록이 없습니다. 새 브랜치의 이름을 정하는 명령이기 때문입니다.

스크립트는 셸의 **현재** 디렉터리에서 가장 가까운 `package.json`에서 가져오므로,
`cd frontend` 뒤에는 프런트엔드의 스크립트가 나옵니다. 입력한 글자로 시작하는 이름이
먼저, 그 글자를 포함하는 이름이 그다음에 옵니다.

목록은 마지막 Enter 이후 입력한 키만 압니다. ↑로 명령을 불러오거나, 커서를 옮기거나,
셸 자체의 Tab 완성을 쓰면 목록이 볼 수 없는 곳에서 줄이 바뀌므로, 엉뚱한 것을 완성하는
대신 다음 Enter까지 조용히 있습니다. Windows에서는 현재 디렉터리를 읽을 수 없어서, 목록은
터미널을 연 폴더를 따릅니다.

## PATH 이야기

셸은 Terminal.app이나 iTerm과 똑같이 **로그인 셸**로 시작해요. 그래서
`~/.zprofile`, `~/.zlogin`, `~/.bash_profile`이 모두 실행됩니다. 버전 관리
도구나 `brew shellenv`는 보통 그 파일들에 자신을 등록하기 때문에 이게
중요해요 — 터미널에서 되는 `fvm`, `nvm`, `pyenv` 같은 도구는 여기서도 됩니다.

Gitcito는 시작할 때 로그인 셸에 진짜 `PATH`를 물어보고, 자신이 띄우는 모든
프로세스에 합쳐 넣어요. Dock에서 실행한 GUI 앱은 거의 아무것도 물려받지 못하기
때문입니다. 그래도 명령을 찾지 못한다면, 그 명령이 대화형 셸이 아니라 로그인
셸의 `PATH`에 있는지 확인해 보세요.

여기서 실행하는 것은 Gitcito 자신의 잠금에 보이지 않아요. 그래서 손으로 입력한 긴
`git rebase`와 UI에서의 클릭이 여전히 부딪힐 수 있어요. 터미널이 무언가를 바꾸면 앱은
디스크에서 다시 읽어 새로고침해요.

## 셸, 테마와 Oh My Posh

Windows에서는 설정 → 레이아웃에서 새 터미널마다 실행할 셸을 고릅니다 — PowerShell,
PowerShell Core(`pwsh`), `cmd`, Git Bash, WSL 또는 직접 지정한 실행 파일. 터미널의 모양
(테마, 글꼴 크기, 글꼴 패밀리)은 설정 → 테마 → 터미널 테마에 있으며 모든 세션에 즉시
적용됩니다.

[Oh My Posh](https://ohmyposh.dev)가 설치되어 있으면, 이 섹션은 `%POSH_THEMES_PATH%`
아래의 모든 `*.omp.json`을 실시간 미리 보기와 함께 보여 줍니다. 하나를 고르면 새
터미널에 `POSH_THEME`으로 전달되므로, 프로필에 있는 평범한 `oh-my-posh init pwsh`가 그
테마를 사용합니다. 직접 지정한 `.omp.json` 경로도 됩니다. 칸을 기본값으로 두면 셸/프로필이나
전역 `POSH_THEME`이 이미 정한 값이 유지됩니다. 열려 있는 세션은 만들 때의 테마를 그대로
씁니다 — 새 테마를 적용하려면 터미널을 닫았다가 다시 여세요. 프롬프트 글리프에는 터미널
글꼴 패밀리에 Nerd Font(예: `CaskaydiaMono Nerd Font`)가 필요하며, 없으면 아이콘이
네모로 보입니다.

속도에 관해: Oh My Posh는 프롬프트마다 바이너리를 한 번 실행합니다 — Windows에서 대략
100~200ms, 큰 저장소에서 git 세그먼트가 있는 테마라면 더 걸립니다. 이는 Gitcito의 지연이
아니라 각 프롬프트 전의 짧은 멈춤으로 느껴집니다. git 세그먼트가 없는 테마가 가장 빠릅니다.
PowerShell의 예측 표시 스타일도 영향을 줍니다. `-PredictionViewStyle InlineView`는 키를
누를 때마다 작은 영역을 다시 그리고, `ListView`는 블록 전체를 다시 그립니다.
