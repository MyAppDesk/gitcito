# التشغيل والتنقيح

يقرأ Gitcito ملف `.vscode/launch.json` عندك — ملف الجذر وأي ملفات متداخلة،
مجمَّعة بفواصل — ويشغّل الإعداد الذي تختاره في الطرفية المدمجة.

![منتقي التشغيل وشريط الأدوات العائم](../../screenshots/launch-configs.webp)

- **متغيرات VS Code تُحَلّ** (مثل `${workspaceFolder}` وأخواته).
- تُنفَّذ **`preLaunchTask`** الخاصة بالإعداد أولًا.
- تُطلب قيم **`${input:…}`** منك تفاعليًا قبل التشغيل (بنوعيها `promptString`
  و`pickString`).
  يعرض `pickString` خياراته كمنتقٍ حقيقي مع تحديد القيمة الافتراضية مسبقًا؛
  ويُخفى إدخال `promptString` المعلَّم بـ `password`.
- تعمل مهام **`isBackground`** (المراقِبات وخوادم التطوير) منفصلةً، فلا تعطّل
  التشغيل أبدًا.
- تشغّل **المجموعات المركّبة (compounds)** كل عضو **كجلسة متوازية مستقلة** —
  في طرفية مقسّمة واحدة تحمل اسم المجموعة، بلوحة لكل عضو، تمامًا مثل جلسات
  التصحيح في VS Code. مع `stopAll: true`، يؤدي إيقاف عضو واحد إلى إيقافها كلها.
  المهام المشتركة بين عدة أعضاء تعمل **مرة واحدة**، في لوحة خاصة بها، قبل بدء
  الأعضاء — فيسأل موجّه رفع الإصدار مرة واحدة، لا مرة لكل عضو.
  تُغلق هذه اللوحة نفسها عند النجاح وتبقى مفتوحة عند الفشل.
- يُحترم **`serverReadyAction`**: عندما يطابق خرج الجلسة النمط المُهيّأ، يُفتح
  عنوان URL المُعلن في متصفحك (`openExternally`؛ كما يفتح `debugWithChrome` /
  `debugWithEdge` المتصفح أيضًا — لا يستطيع Gitcito إرفاق مصحّح).

![مجموعة مركّبة تشغّل جلستين متوازيتين](../../screenshots/launch-compound.webp)

![منتقي ${input} مع القيمة الافتراضية محددة مسبقًا](../../screenshots/launch-input.webp)

يمنحك شريط أدوات عائم **إيقافًا مؤقتًا واستئنافًا وإعادة تشغيل وإيقافًا**،
ويبدّل بين الجلسات العاملة.

فعّله من **الإعدادات ← عام ← تمكين launch.json**. عندها يظهر زر **LAUNCH**
بجوار تبويبَي Git والملفات.

يظهر عضو المجموعة المركّبة بصيغة *المجموعة › العضو*، وإعادة تشغيله تعيد تشغيل
ذلك العضو وحده.
إذا غطّى الشريط شيئًا تحتاجه، اسحبه جانبًا من مقبضه — يُحفظ الموضع، والنقر المزدوج على المقبض يعيده إلى المنتصف.

ما لا يفعله Gitcito عمدًا: إنه يشغّل برامجك في طرفيات حقيقية، لكنه ليس مصحّحًا —
لا نقاط توقف، ولا فحص متغيرات، ولا Debug Adapter Protocol. تعمل تكوينات attach
عندما تحمل `preLaunchTask` (المهمة هي العمل)؛ أما attach الخالص فلا شيء لديه
ليُشغَّل.
