# Коммиты

## Стили сообщений

Выберите один в настройках; редактор подстроится под него.

| Стиль | Как выглядит |
|---|---|
| **Conventional** | `feat(api)!: add rate limiting` — с выпадающим списком типов |
| **Gitmoji** | `✨ add rate limiting` — с выбором эмодзи |
| **Gitmoji + Conventional** | `✨ feat(api): add rate limiting` — выбор эмодзи *и* список типов |
| **Ticket** | `ABC-123: add rate limiting` — подставляется из имени ветки |
| **Plain** · **Auto** | Всё, что напечатаете; в режиме Auto форму выбирает ИИ |
| **Caveman** · **Haiku** | Ровно то, на что похоже название |

![Редактор сообщения, заполненный из шаблона коммита](../../screenshots/commit-template.webp)

### Gitmoji

[Gitmoji](https://gitmoji.dev) ставит эмодзи перед темой, чтобы историю можно
было прочитать с одного взгляда: 🐛 исправления, ✨ новые функции, 🔥 удаления.
В обоих стилях gitmoji кнопка эмодзи находится прямо рядом с полем темы. Она
открывает **все 75 официальных gitmoji** с поиском по эмодзи, по `:коду:` (то,
что набирают пользователи gitmoji-cli) или по смыслу на вашем языке.

**Gitmoji + Conventional** держит тип и эмодзи согласованными. Выберите тип — и
эмодзи последует за ним; смените тип — и эмодзи сменится тоже, если только вы не
выбрали его вручную (например, 🚑️ для `fix`). Такой эмодзи никогда не
перезаписывается.

| Тип | Emoji | Тип | Emoji |
|---|---|---|---|
| `feat` | ✨ | `test` | ✅ |
| `fix` | 🐛 | `build` | 📦️ |
| `docs` | 📝 | `ci` | 👷 |
| `style` | 🎨 | `chore` | 🔧 |
| `refactor` | ♻️ | `revert` | ⏪️ |
| `perf` | ⚡️ | | |

ИИ пишет в том же формате. Если модель забудет эмодзи или ответит
`:shortcode:`, тема будет исправлена до того, как попадёт в поле.

Коммиты, которые другие инструменты записали как `:sparkles: add login`,
**показываются** как `✨ add login` в графе, в деталях коммита и в окнах
истории.

Ограничения:

- Выбор всегда записывает эмодзи в **unicode**, никогда `:shortcode:`.
- Шорткоды преобразуются только при отображении. Сам коммит не переписывается,
  а поиск по истории ищет текст в том виде, в каком он был закоммичен.
- Учитываются только gitmoji: тема, начинающаяся с другого эмодзи, остаётся как есть.
- Репозиторий, у которого хук `commit-msg` запускает commitlint со стандартным
  пресетом Conventional, отклоняет эмодзи в начале. Это правило хука, а не
  Gitcito: настройте commitlint под gitmoji или используйте там чистый
  Conventional.

## Что редактор делает за вас

- <kbd>↑</kbd> <kbd>↓</kbd> вызывают ваши **недавние сообщения**.
- **Выбор соавторов** добавляет трейлеры `Co-authored-by:` из списка
  контрибьюторов самого репозитория.
- `commit.template` / `.gitmessage` **предзаполняют** сообщение, строки с
  комментариями вырезаются.
- Во время слияния, cherry-pick или revert сообщение **заполняется заранее** так
  же, как это сделал бы git.
- Черновики **сохраняются** для каждого репозитория, так что переключение
  вкладок никогда не теряет сообщение.

## Линтер

Живая, ничего не блокирующая проверка: длина заголовка (со счётчиком символов),
точка в конце, заголовок не в повелительном наклонении или со строчной буквы,
слишком широкие строки тела. Подсказки, а не шлагбаум — они не помешают вам
закоммитить.

## Amend

Amend переписывает последний коммит тем, что проиндексировано. Gitcito сначала
показывает существующее сообщение, чтобы вы его редактировали, а не набирали
заново.

**Исправить коммит…** на строке графа делает то же самое для HEAD: загружает
полное сообщение, переводит редактор в режим amend и ставит на него фокус.
Уже отправленный HEAD всё равно можно исправить, но Gitcito предупредит, что
обновление удалённого репозитория потребует форс-пуша.

**Отменить коммит…** — его собрат для неотправленного HEAD: mixed-сброс на
родителя, изменения рабочего дерева сохранены, сообщение возвращено в редактор.
У первого коммита есть отдельный путь, который оставляет нерождённую ветку
вместо уничтожения файлов.
