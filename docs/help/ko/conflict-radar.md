# 충돌 레이더

브랜치가 충돌하는지 알아보려고 실제로 머지해 보는 건 질문 하나에 치르는 값으로는
너무 비싸요. 레이더가 먼저 답해 줘요.

Gitcito는 당신이 고른 기준으로 모든 브랜치를 **객체 데이터베이스 안에서**
머지해 봐요(`git merge-tree --write-tree`). 체크아웃도, 인덱스 변경도, 작업 트리
변경도 없고, 나중에 치울 것도 없어요. 스캔이 도는 동안 커밋하지 않은 작업은 있던
자리에 그대로 있어도 돼요.

![브랜치마다 판정 하나씩 보여 주는 레이더](../../screenshots/conflict-radar.webp)

![브랜치를 하나씩 스캔한 뒤 다툼이 있는 파일들을 여는 모습](../../screenshots/clip-conflict-radar.webp)

## 사용하기

도구 메뉴, <kbd>⌘K</kbd> → *충돌 레이더* 에서 열거나, 브랜치를 오른쪽 클릭해서
**그** 브랜치를 기준으로 전부 스캔할 수 있어요.

열자마자 현재 브랜치를 기준으로 스캔을 시작해요.

| 판정 | 뜻 |
|---|---|
| **충돌 예상** | 머지하려면 손이 필요해요. 정확한 경로가 나열돼요. |
| **깨끗하게 머지됨** | 다툼 없이 적용될 거예요. |
| **이미 포함됨** | 기준이 이미 담고 있어요 — 머지할 것이 없어요. |
| **실패** | git이 거부했어요: 관련 없는 히스토리, 없는 ref. 이유가 표시돼요. |

브랜치는 나쁜 것부터 정렬되고, 그중에서도 가장 나쁜 것 — 가장 많은 파일을 건드리는
브랜치 — 이 맨 위로 올라와요.

## 다툼이 있는 파일

그 아래의 **다툼이 있는 파일** 은 몇 개의 브랜치가 그 경로를 고쳐 쓰고 있는지로
경로에 순위를 매겨요. 두 브랜치가 파일 하나를 두고 다투고 있다면 지금 나눠야 할
대화이고, 다섯이라면 설계 문제예요.

## 스캔한 뒤

사이드바의 브랜치 행에 색깔 점이 붙어요. 빨강은 충돌 예상, 초록은 깨끗함,
주황은 git이 거부한 브랜치예요. 이미 기준에 담긴 브랜치에는 점이 붙지 않아요 —
이미 머지된 모든 것에 회색 점이 줄지어 있어 봐야 잡음일 뿐이니까요.

> 스캔은 아무것도 바꾸지 않아요. `git status` 는 깨끗한 채로 있고 HEAD도 움직이지
> 않아요.
