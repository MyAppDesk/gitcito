# Перевірка середовища

Деякі збої зовсім не стосуються репозиторію. Вони йдуть від машини: git,
застарий для входу через профіль, термінал, що мовчки перейшов у базовий режим,
вхід GitHub CLI, який не може пушити файли workflow. Кожен із них потім спливає
розмитою помилкою посеред чогось іншого. **Налаштування → Середовище** (також
*Settings: Environment* у палітрі команд) перевіряє їх заздалегідь.

[Лікар репозиторію](repo-settings.md) відповідає на інше питання: чи можна
зібрати *цей репозиторій* тут, виходячи з того, чого вимагає його `.gitcito.json`.
Перевірка середовища стосується самого застосунку й однакова для будь-якого
репозиторію.

![Перевірки середовища в Налаштуваннях](../../screenshots/settings-environment.webp)

## Що перевіряється

| Рядок | Зелений означає | Жовтий або червоний означає |
|-------|-----------------|-----------------------------|
| **Git** | git 2.31 або новіший є в `PATH` | Старіший за 2.31: обліковий запис [профілю](profiles.md) не може увійти для fetch і push. Відсутній: нічого не працює, доки git не встановлено |
| **Git LFS** | `git lfs` встановлено | Не встановлено. Потрібен лише репозиторіям, що зберігають файли в LFS |
| **Термінал** | Нативний термінал завантажився | [Термінал](terminal.md) працює в базовому режимі: без кольорів, без зміни розміру, без повноекранних програм |
| **Credential helper** | У git є helper для паролів HTTPS — глобально або для окремих хостів (те, що налаштовує `gh auth setup-git`) | Helper’а немає, тож git поза Gitcito питає щоразу. Або `store`, який зберігає їх відкритим текстом. Див. [Credential helper](credentials.md) |
| **GitHub CLI** | `gh` увійшов зі scope `workflow` | Увійшов без нього: GitHub відхиляє будь-який push, що змінює `.github/workflows` |
| **Відстеження файлів** (Linux) | Ліміт inotify щонайменше 65 536 | Менший ліміт вичерпується з кількома великими відкритими репозиторіями, і нові теки перестають оновлювати статус |

Незастосовний рядок не показується: GitHub CLI, якщо його не встановлено або не
виконано вхід, і відстеження файлів у macOS та Windows.

## Як виправити знайдене

Де є виправлення, рядок показує його як команду з кнопкою копіювання. Наприклад,
`gh auth refresh -h github.com -s workflow` додає відсутній scope, а рядок
`sysctl` піднімає ліміт inotify. **Сторінка сама ніколи нічого не запускає.**
Деякі виправлення потребують `sudo` або змінюють глобальну конфігурацію —
прочитайте їх перед запуском. Потім натисніть **Перевірити знову**.

## Обмеження

- Перевіряється те, що застосунок бачить із власного процесу. Профіль оболонки,
  що змінює `PATH` лише у вашому терміналі, може спричинити розбіжність.
- Рядок GitHub CLI відображає власний вхід `gh`, а не облікові записи,
  під’єднані в **Налаштування → Інтеграції**. Це різні облікові дані. Брак scope
  `workflow` там проявиться як відхилений push.
- Вона повідомляє, що встановлено. Нічого не встановлює й не оновлює.
