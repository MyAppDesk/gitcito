# Вбудований термінал

Справжній PTY (xterm + node-pty), а не запускач команд. Ваша оболонка, ваш
промпт, ваші аліаси.

![Вбудований термінал](../../screenshots/terminal.webp)

- **Кілька вкладок на репозиторій**, кожна стартує в теці цього репозиторію.
- Пришвартуйте його **під** графом або як **праву колонку**; панель запам’ятовує
  свій розмір.
- Видимість термінала — окрема для кожного репозиторію: перехід на вкладку, де
  його ніколи не відкривали, залишає його закритим.
- Вкладки називають себе за тим, що в них виконується.
- Згорнутий список терміналів стискається до **рейки**: одна іконка на термінал
  (розділені термінали показують міні-карту панелей), клацніть, щоб перемкнутися,
  клацніть правою кнопкою — і отримаєте звичне меню перейменування/розділення/
  завершення.
- **Перетягніть один термінал на інший** у списку, щоб об'єднати їх у
  розділену групу. Кожен термінал зберігає своє ім'я як панель; група отримує
  нове нумероване ім'я.

![Дві панелі, розділені пліч-о-пліч в одній групі терміналів](../../screenshots/terminal-split.webp)

## Клавіші

| Клавіші | Дія |
|---|---|
| <kbd>⌃`</kbd> | Показати або сховати термінал — фізична клавіша Control, на будь-якій платформі |
| <kbd>⌘T</kbd> / <kbd>Ctrl+T</kbd> | Новий термінал, поки фокус у терміналі |
| <kbd>⌘W</kbd> / <kbd>Ctrl+W</kbd> | Закрити активний термінал; закриття останнього ховає панель |
| <kbd>Ctrl+Shift+C</kbd> | Копіювати виділення; звичайний <kbd>Ctrl+C</kbd> теж копіює, поки є виділення, а без нього лишається SIGINT |
| <kbd>Ctrl+V</kbd> / <kbd>Ctrl+Shift+V</kbd> / <kbd>Shift+Ins</kbd> | Вставити з буфера обміну |
| Правий клік | Копіює виділення або вставляє, якщо нічого не виділено |

Перші дві навмисно працюють лише в терміналі: поза ним вони, як і раніше,
відкривають і закривають [вкладки робочого простору](workspaces.md). У macOS
«Копіювати» та «Вставити» з меню «Редагування» працюють так само.

## Підказки скриптів

Наберіть `npm run ` (або `pnpm`, `yarn`, `bun run`) — і біля курсора з’явиться
список скриптів проєкту, що фільтрується під час введення: `npm run loc` знаходить
`LOCAL_SERVER`. Біля кожної назви — команда, яку вона запускає.

| Клавіша | Дія |
|---------|-----|
| **Tab** | Доповнює вибраний скрипт |
| **↑ / ↓** | Вибрати інший |
| **Esc** | Закриває список до наступного введення |

Інші команди мають свій список:

| Набрано | Показує | Звідки |
|-------|-------|------|
| `composer run ` | Скрипти Composer | найближчий `composer.json` |
| `make ` | Цілі Makefile, з `## текстом` після цілі як описом | `Makefile` поточного каталогу, як його читає `make` |
| `git checkout `, `switch`, `merge`, `rebase` | Локальні гілки, потім віддалені за короткою назвою | репозиторій, у якому перебуває оболонка |

Ціль Makefile, зібрана зі змінних або шаблону (`%.o`), не показується, а
`git checkout -b` списку не отримує: він дає назву новій гілці.

Скрипти беруться з `package.json`, найближчого до **поточного** каталогу
оболонки, тож після `cd frontend` ви бачите скрипти фронтенду. Спершу йдуть назви,
що починаються з набраного, потім — ті, що його містять.

Список знає лише клавіші, набрані після останнього Enter. Виклик команди
стрілкою ↑, переміщення курсора чи власне Tab-доповнення оболонки змінюють рядок
поза його полем зору, тож він мовчить до наступного Enter, а не доповнює не те. У
Windows поточний каталог прочитати не можна, тож список іде за текою, в якій
відкрито термінал.

## Ваш PATH

Оболонка стартує як **оболонка входу (login shell)**, так само як у Terminal.app
чи iTerm, тож `~/.zprofile`, `~/.zlogin` і `~/.bash_profile` виконуються. Це
важливо, бо менеджери версій і `brew shellenv` зазвичай прописуються саме там —
інструмент на кшталт `fvm`, `nvm` чи `pyenv`, який працює у вашому терміналі,
працює й тут.

Ще Gitcito на старті питає у вашої оболонки входу її справжній `PATH` і
домішує його в усе, що запускає, бо GUI-застосунок, відкритий із Dock, майже
нічого не успадковує. Якщо команда все одно не знаходиться, перевірте, що вона є
в `PATH` саме оболонки входу, а не лише інтерактивної.

Усе, що ви запускаєте тут, невидиме для власного блокування Gitcito, тож довгий
`git rebase`, набраний руками, і клацання в інтерфейсі все одно можуть зіткнутися
— застосунок перечитує стан із диска, коли термінал щось змінює.

## Оболонка, тема та Oh My Posh

У Windows розділ Налаштування → Макет вибирає оболонку, яку запускає кожен новий
термінал, — PowerShell, PowerShell Core (`pwsh`), `cmd`, Git Bash, WSL або власний
виконуваний файл. Вигляд термінала (тема, розмір і сімейство шрифту) — у
Налаштування → Теми → Тема термінала, і він одразу застосовується до всіх сеансів.

Якщо встановлено [Oh My Posh](https://ohmyposh.dev), розділ також показує кожен
`*.omp.json` із `%POSH_THEMES_PATH%` з живим попереднім переглядом — вибрана тема
передається новим терміналам як `POSH_THEME`, тож звичайний
`oh-my-posh init pwsh` у вашому профілі її підхопить. Власний шлях до `.omp.json`
теж працює; якщо лишити поле «Типово», збережеться те, що вже задають
оболонка/профіль або глобальний `POSH_THEME`. Відкриті сеанси зберігають свою
тему — закрийте й знову відкрийте термінал, щоб застосувати нову. Для гліфів
запрошення потрібен Nerd Font у сімействі шрифту термінала (наприклад,
`CaskaydiaMono Nerd Font`), інакше значки будуть квадратиками.

Щодо швидкості: Oh My Posh запускає свою програму при кожному запрошенні —
близько 100–200 мс у Windows, довше для тем із git-сегментом у великому
репозиторії, — і це відчувається як коротка пауза перед кожним запрошенням, а не
як затримка Gitcito. Теми без git-сегмента найшвидші. Важить і стиль підказок
PowerShell: `-PredictionViewStyle InlineView` перемальовує невелику ділянку на
кожне натискання, а `ListView` — цілий блок.
