# アブソーブ

3 つのファイルにまたがるレビュー指摘を 3 件直しました。誠実なやり方は、正しい親を
指す `fixup!` コミットを 3 つ作ることです。実際に人がやるのは、「review fixes」という
名前のコミット 1 つです。

アブソーブは、その誠実なやり方をあなたの代わりにやります。

![ステージした各ハンクを、それを持ち込んだコミットへ振り分けるアブソーブ](../../screenshots/absorb.webp)

## 仕組み

1. 修正をステージします。
2. ツール → **ステージした変更をアブソーブ…**（または <kbd>⌘K</kbd>）。
3. Gitcito は、ステージされた各ハンクが触れている行を blame し、**まだプッシュして
   いないあなたのコミット** のどれがそれを持ち込んだのかを突き止め、何かをする前に
   計画を見せます。

計画には、送り先のコミットごとに向かうハンクが並び、さらに **まだどこにも属さない**
というグループが付きます。新規作成したファイルには吸収される先の履歴がないので、
ステージされたまま残り、いつもどおりコミットできます。

| ボタン | 起きること |
|---|---|
| **fixup を作成** | 送り先ごとに `fixup!` コミットを 1 つ。リベースはしません。 |
| **fixup を作成してリベース** | 同じことをしたうえで、autosquash のリベースで畳み込みます。 |

## 守っているルール

- **候補になるのは未プッシュのコミットだけです。** すでに公開されたものは、こちらが
  書き換えてよいものではありません。すべてプッシュ済みなら、アブソーブはそう伝えて
  何もしません。
- **作業ツリーには決して触れません。** 触るのはインデックスと、アブソーブ自身が作った
  コミットだけです。
- **失敗しても散らかしません。** どこかで失敗した場合、HEAD とインデックスは元の
  ままに戻されます。
- マージやリベースの最中は実行を拒否します。そのインデックスは git のものだからです。
