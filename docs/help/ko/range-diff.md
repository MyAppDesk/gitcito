# 그동안 바뀐 것

브랜치를 리뷰했어요. 그런데 누군가 리베이스한 뒤 강제 푸시를 했어요. 이제 평범한
diff는 아무 쓸모가 없어요. 리베이스 이후의 모든 커밋은 새 커밋이라서, 전부 새것처럼
보이거든요.

`git range-diff`는 두 버전을 커밋 단위로 짝지어 주고, Gitcito는 예전 위치를
**reflog**에서 곧바로 읽어 와요 — 그래서 이 기능이 작동하려고 미리 기록해 둬야
했던 것은 아무것도 없어요.

![강제 푸시 이후의 재작성·신규·삭제된 커밋](../../screenshots/range-diff.webp)

| 판정 | 뜻 |
|---|---|
| **재작성됨** | 같은 커밋인데 내용이 바뀌었어요. 펼치면 인터디프가 보여요 — 파일 전체가 아니라 메시지 손질과 추가된 검사만요. |
| **신규** | 마지막으로 본 뒤에 추가됐어요. |
| **삭제됨** | 마지막으로 본 뒤에 사라졌어요. |
| **그대로** | 재작성에도 손대지 않고 살아남았어요. |

## 들어가는 방법

- **재작성된 히스토리를 발견한 페치는 그 사실을 알려 줘요.** 토스트가 브랜치
  이름을 알려 주고, 원격 아래의 그 행에 **⟳**가 생겨요. 그걸 누르면 예전에
  가리키던 바로 그 커밋에서 비교가 열려요.
- 아무 브랜치나 우클릭 → *그동안 바뀐 것…*
- <kbd>⌘K</kbd> → *그동안 바뀐 것*

## 이전 위치들

레퍼런스 입력란 아래의 칩은 그 브랜치의 reflog예요. 강제 업데이트, 리베이스,
리셋이 각각 언제 일어났는지와 함께 나와요. 하나를 고르면 그 지점을 기준으로 비교가
다시 실행돼요. 이게 이 기능의 전부예요 — 브랜치가 어디에 있었는지의 역사는 이미
여러분 디스크에 있으니까요.
