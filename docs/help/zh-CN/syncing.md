# 获取、拉取与推送

## 拉取

三种模式，从下拉菜单里选：**默认**、**仅快进**或**变基**。本地改动会在拉取前后自动贮藏再恢复，所以工作区脏着也不会把你挡住。

## 推送

强制推送一律使用 `--force-with-lease`——那个安全的变体，只要远程在你上次查看之后动过就拒绝执行。对**受保护分支**做强制推送会要求确认（名单在仓库设置的齿轮里）。

![受保护分支在强制推送前要求的确认](../../screenshots/force-push-guard.webp)

### 不止一个远程

**推送**按钮指向分支的上游。一旦仓库有了不止一个远程，旁边的箭头还会提供：

| | |
|---|---|
| **推送到某一个远程** | 挑一个远程——一个复刻、一个镜像、一个部署目标 |
| **推送到全部 N 个远程** | 每个远程一次推送，按顺序来 |
| **把所有标签推送到** | `git push <remote> --tags`，本地全部标签一次送出去 |

同样这两个动作也在侧边栏里每个远程自己那一行上，而问题冒出来的时候，你通常正好就在那儿。

**一个被拒绝，不会取消其余的。** 同时推送一个复刻和它的上游，恰恰就是一边拒绝、另一边仍然该走通的场景，所以每个远程各报各的：成功的在一条提示里点名，每个失败的单独一条，附上 git 给的理由。

只有列表里的**第一个**远程会设置分支的上游。一个分支只有一个上游，而最后被推送的那个远程未必就是你想让它跟踪的那个。

两条路径都会走和普通推送一样的检查——受保护分支的确认，以及[密钥守卫](security.md)。往两个远程发布是双倍的暴露，不是一半的谨慎。

## 获取

在每个远程上**获取全部并修剪**，另外还有按你设定的间隔在后台跑的**自动获取**（设置 → 通用），以及工具栏上那枚「X 之前获取过」的徽标。

一次获取如果发现**历史被重写**，它会说出来：一条提示点名那个分支，那一行会多出一个标记，点开就是[自那以后改了什么](range-diff.md)，起点正是它原先指向的那个提交。

## 一次面对多个仓库

- 一个分组标签页可以对它整棵子树**获取全部 / 拉取全部**。
- [任务中心](mission-control.md)在整个工作空间里做同样的事，而且可以*只*拉取那些确实落后的仓库。

## 远程

在侧边栏里添加、编辑、删除远程，也可以单独获取某一个。分支行带有按远程划分的存在徽标，所以一眼就能看出哪些远程有这个分支的副本。
