# Flutter DevTools

В DevTools уже есть сетевая вкладка, таймлайн, инспектор виджетов и профайлер
памяти — и это Flutter-веб-приложение, которое отдаётся с вашей же машины.
Поэтому Gitcito ничего из этого не переписывает и сам с Dart VM Service не
разговаривает: он замечает адрес и встраивает его.

![DevTools во вкладке Gitcito](../../screenshots/devtools.webp)

`flutter run` печатает строку, как только VM service поднялся:

```
The Flutter DevTools debugger and profiler on iPhone 16 Pro is available at:
http://127.0.0.1:9100?uri=http://127.0.0.1:53412/uJ8k=/
```

Сессия запуска следит за собственным выводом, и на панели отладки появляется
кнопка. Клик открывает DevTools в отдельной вкладке — по одной на сессию: два
запущенных приложения это два DevTools.

**Горячий перезапуск публикует новый адрес**, и вкладка следует за ним, пока жива
её сессия. Когда сессия исчезает, вкладка хранит последний адрес, обычно уже
мёртвый: закройте её и откройте DevTools из нового запуска.

## Что ему позволено

Встроенный вид держат на коротком поводке — приложение хранит учётные данные:

- **Только loopback.** `127.0.0.1`, `localhost`, `::1`. Встраивание любого
  другого адреса отклоняется, как и переход на него.
- **Никакого preload, node integration выключен, изоляция контекста включена.**
  У страницы нет моста внутрь Gitcito.
- **Ссылки открываются в настоящем браузере**, в обычном окне, а не в панели.

## Ограничения

- **Это DevTools, а не наша поделка.** Что умеет та версия, умеет и панель; чего
  не умеет — не умеем и мы. Сетевой вкладки «от Gitcito» нет.
- **Так объявляется только Flutter.** Обычная программа на Dart печатает URL
  VM service, но не адрес DevTools, — и кнопка не появляется.
- **Пустая панель означает, что приложение остановилось.** DevTools отдаёт
  *работающее приложение*; когда оно завершается, адрес перестаёт отвечать.
