# الطرفية المدمجة

طرفية PTY حقيقية (xterm مع node-pty)، لا مجرد مشغّل أوامر. صدفتك أنت، ومحثّك
أنت، واختصاراتك أنت.

![الطرفية المدمجة](../../screenshots/terminal.webp)

- **تبويبات متعددة لكل مستودع**، يبدأ كل منها في مجلد ذلك المستودع.
- أرسِها **أسفل** الرسم البياني أو بوصفها **عمودًا جانبيًا**؛ واللوحة تتذكر
  حجمها.
- ظهور الطرفية يُحدَّد لكل مستودع: الانتقال إلى تبويب لم يفتح طرفية قط يُبقيها
  مغلقة.
- تسمّي التبويبات نفسها بحسب ما يعمل داخلها.
- طيّ قائمة الطرفيات يقلّصها إلى **شريط**: أيقونة لكل طرفية (والطرفيات المقسومة
  تعرض خريطة لوحات مصغّرة)، انقر للتبديل، وانقر بالزر الأيمن لقائمة إعادة
  التسمية والقسمة والإنهاء المعتادة.
- **اسحب طرفية فوق أخرى** في القائمة لدمجهما في مجموعة مقسّمة. تحتفظ كل طرفية
  باسمها كلوحة؛ وتحصل المجموعة المدموجة على اسم مرقّم جديد.

![لوحتان مقسومتان جنبًا إلى جنب في مجموعة طرفية واحدة](../../screenshots/terminal-split.webp)

## المفاتيح

| المفاتيح | الوظيفة |
|---|---|
| <kbd>⌃`</kbd> | إظهار الطرفية أو إخفاؤها — مفتاح Control الفعلي، على كل الأنظمة |
| <kbd>⌘T</kbd> / <kbd>Ctrl+T</kbd> | طرفية جديدة، ما دامت الطرفية في التركيز |
| <kbd>⌘W</kbd> / <kbd>Ctrl+W</kbd> | إغلاق الطرفية النشطة؛ إغلاق آخر طرفية يُخفي اللوحة |
| <kbd>Ctrl+Shift+C</kbd> | نسخ التحديد؛ و<kbd>Ctrl+C</kbd> وحده ينسخ أيضًا ما دام هناك تحديد، ويبقى SIGINT حين لا يوجد |
| <kbd>Ctrl+V</kbd> / <kbd>Ctrl+Shift+V</kbd> / <kbd>Shift+Ins</kbd> | اللصق من الحافظة |
| النقر الأيمن | ينسخ التحديد، أو يلصق إن لم يكن هناك شيء محدد |

الاختصاران الأولان يعملان داخل الطرفية فقط عن قصد: خارجها يظلان يفتحان ويغلقان
[ألسنة مساحة العمل](workspaces.md). وفي macOS يعمل نسخ/لصق من قائمة «تحرير» بالطريقة
نفسها.

## اقتراحات السكربتات

اكتب `npm run ` (أو `pnpm` أو `yarn` أو `bun run`) فتظهر عند المؤشر قائمة بسكربتات
المشروع، تُصفّى أثناء الكتابة: `npm run loc` يجد `LOCAL_SERVER`. ويعرض كل اسم الأمر الذي
يشغّله.

| المفتاح | الوظيفة |
|---------|---------|
| **Tab** | يكمل السكربت المحدد |
| **↑ / ↓** | اختيار سكربت آخر |
| **Esc** | يغلق القائمة حتى تكتب مجددًا |

لأوامر أخرى قوائمها الخاصة:

| المكتوب | يعرض | يُقرأ من |
|-------|----|--------|
| `composer run ` | سكربتات Composer | أقرب `composer.json` |
| `make ` | أهداف Makefile، مع `## النص` بعد الهدف وصفًا له | ملف `Makefile` في المجلد الحالي، كما يقرؤه `make` |
| `git checkout ` و`switch` و`merge` و`rebase` | الفروع المحلية، ثم البعيدة باسمها المختصر | المستودع الذي توجد فيه الصدفة |

لا يظهر هدف Makefile مبني من متغيرات أو نمط (`%.o`)، ولا يحصل
`git checkout -b` على قائمة: فهو يسمّي فرعًا جديدًا.

تأتي السكربتات من أقرب `package.json` إلى المجلد **الحالي** للصدفة، فبعد `cd frontend`
تحصل على سكربتات الواجهة الأمامية. تأتي الأسماء التي تبدأ بما كتبته أولًا، ثم الأسماء التي
تحتويه.

لا تعرف القائمة إلا المفاتيح التي كتبتها منذ آخر Enter. استدعاء أمر بالسهم ↑، أو تحريك
المؤشر، أو استخدام إكمال Tab الخاص بالصدفة يغيّر السطر بعيدًا عن نظرها، لذا تبقى صامتة حتى
Enter التالي بدل أن تكمل شيئًا خاطئًا. على Windows لا يمكن قراءة المجلد الحالي، فتتبع
القائمة المجلد الذي فُتحت فيه الطرفية.

## مسار PATH لديك

تبدأ الصدفة كـ **صدفة تسجيل دخول (login shell)**، تمامًا مثل Terminal.app أو
iTerm، لذا تُنفَّذ ملفات `~/.zprofile` و`~/.zlogin` و`~/.bash_profile`. هذا مهم
لأن مديري الإصدارات و`brew shellenv` يثبّتون أنفسهم هناك عادةً — فأداة مثل `fvm`
أو `nvm` أو `pyenv` تعمل في طرفيتك تعمل هنا أيضًا.

كما يسأل Gitcito صدفة تسجيل الدخول عن قيمة `PATH` الحقيقية عند الإقلاع ويدمجها في
كل ما يشغّله، لأن تطبيقًا رسوميًا يُفتح من الـ Dock لا يرث تقريبًا أي شيء. إن ظل
أمر ما غير موجود، فتحقّق من أنه ضمن `PATH` لصدفة تسجيل دخول لا لصدفة تفاعلية فقط.

كل ما تشغّله هنا غير مرئي لآلية القفل الخاصة بـ Gitcito، فقد يتصادم أمر
`git rebase` طويل كتبته بيدك مع نقرة في الواجهة — والتطبيق يحدّث حالته من القرص
حين تغيّر الطرفية شيئًا.

## الصدفة والسمة وOh My Posh

على Windows، يختار الإعدادات ← التخطيط الصدفة التي تشغّلها كل طرفية جديدة — PowerShell أو
PowerShell Core (`pwsh`) أو `cmd` أو Git Bash أو WSL أو ملفًا تنفيذيًا مخصصًا. أما مظهر
الطرفية (السمة وحجم الخط وعائلته) فموجود في الإعدادات ← السمات ← سمة الطرفية، ويُطبّق فورًا
على كل الجلسات.

إذا كان [Oh My Posh](https://ohmyposh.dev) مثبتًا، يعرض هذا القسم أيضًا كل `*.omp.json`
في `%POSH_THEMES_PATH%` مع معاينة حية — واختيار أحدها يمرّره إلى الطرفيات الجديدة على أنه
`POSH_THEME`، فيلتقطه سطر بسيط `oh-my-posh init pwsh` في ملفك الشخصي. ويعمل أيضًا مسار
`.omp.json` مخصص؛ وترك الحقل على «افتراضي» يُبقي ما تضبطه صدفتك أو ملفك الشخصي أو
`POSH_THEME` العام. تحتفظ الجلسات المفتوحة بسمتها — أغلق الطرفية وأعد فتحها لتطبيق سمة
جديدة. تحتاج رموز المحث إلى خط Nerd Font في عائلة خط الطرفية (مثل
`CaskaydiaMono Nerd Font`)، وإلا ظهرت الأيقونات مربعات.

عن السرعة: يشغّل Oh My Posh برنامجه مرة لكل محث — نحو 100–200 مللي ثانية على Windows،
وأكثر للسمات التي فيها قسم git في مستودع كبير — ويُحسّ ذلك توقفًا قصيرًا قبل كل محث، لا
بطئًا في Gitcito. السمات التي لا تحوي قسم git هي الأسرع. ويؤثر أيضًا نمط التنبؤ في
PowerShell: `-PredictionViewStyle InlineView` يعيد رسم مساحة صغيرة مع كل ضغطة، بينما
`ListView` يعيد رسم كتلة كاملة.
