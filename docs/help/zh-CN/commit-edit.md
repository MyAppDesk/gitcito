# 编辑任意提交

错别字在三周前的一个提交里。常规的修法是交互式变基：停在那个提交上，编辑，继续，
然后祈祷。Gitcito 的修法是：右键点击提交，**编辑此提交**，改好文字，完成。提交
详情面板里的钢笔按钮打开的也是同一个编辑器。

![正在编辑一个历史提交](../../screenshots/commit-edit.webp)

## 它做什么

选中任意一个到 `HEAD` 之间路径为线性的提交。模态框会显示它的文件和提交信息，两者
都可以编辑。接下来会发生两件事：

1. **预览级联**会把被编辑提交之上的每一个提交*在内存中*重放一遍（一串
   `merge-tree` 拣选 — 没有检出，没有工作区，没有 ref）。每个后代提交都会显示为
   绿色或红色，所以在**任何东西真正移动之前**，你就知道这次编辑是干净地传播下去，
   还是会与后来的改动相撞。
2. **改写历史**才是动真格的：同一条链用底层命令构建出来，然后分支用
   `reset --keep` 移动过去 — 你未提交的改动会被一并带上，否则重置中止，什么都没有
   发生。执行前会先拍一份[守护快照](recovery.md)，撤销则会恢复原来的提交链。

每个被重放提交的作者信息和日期都保持不变；变的只有哈希 — 这正是改写历史的含义。

## 级联发生冲突时

某个后来的提交改动了你正在编辑的那些行。预览会把该提交连同冲突文件一起标为红色，
改写会拒绝执行 — 绝不会出现只应用了一半的情况。要么换一种改法，要么用
[交互式变基](rebase.md)正面解决冲突。

## 限制

- **仅限线性历史。** 提交与 `HEAD` 之间若有合并提交，编辑会被禁用 — 重放合并是另
  一个更难的问题。
- 二进制文件和超过 2 MB 的文件会显示但不可编辑。
- 已经推送到远程的提交也可以编辑，但你的下一次推送将不得不是**强制推送** — 模态框
  会在你做出这个决定之前发出警告。
- 提交中被删除的文件无法编辑（没有内容可编辑）。
