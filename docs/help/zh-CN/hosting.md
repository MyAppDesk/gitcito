# 托管与拉取请求

## 创建

不用离开这个应用就能创建拉取请求（PR，在有些平台上叫合并请求）：分支下拉框、由该分支的提交预填好的标题和正文、一个草稿开关，以及——在 GitHub 上——创建时就一并设好的评审者、标签和指派人。

![创建一个拉取请求](../../screenshots/create-pr.webp)

**GitHub、GitLab、Bitbucket 和 Azure DevOps** 都能用。四家平台上打开着的 PR/MR 都列在侧边栏里。

可以从分支对比、提交图、PR 面板里的 `+`，或者从一个议题出发创建（后者会自动填上 `Closes #N`）。

## 评审——GitHub

| | |
|---|---|
| **对话** | 评论与评审状态 |
| **检查** | CI 检查任务，带通过／失败／等待中状态和查看日志的链接 |
| **已看过的文件** | 每个文件一个 ✓ 的清单，带进度 |
| **行内讨论串** | 按 `file:line` 归组的行评论，附上它所在的变更块，以及回复 |
| **动作** | 评论、批准、要求修改，以及合并 / 压缩合并 / 变基合并 |

如果有人在评审进行到一半时强制推送，[自那以后改了什么](range-diff.md)会准确告诉你哪些东西动了。

## 议题、里程碑、发布——GitHub

浏览议题，并打开一个完整的议题标签页：正文、评论、标签、指派人、里程碑、Projects v2 字段、关闭／重新打开，以及**为这个议题创建一个分支**（可由 AI 起名）。里程碑会显示进度和它下面的议题。发布可以连同变更日志页面一起浏览。

## 通知——GitHub

你的整个收件箱——评审请求、提及、CI 动态——覆盖每一个仓库，带未读／全部筛选和标记为已读。工具栏上的铃铛带一个未读徽标，还可以选择在有人请求评审或 CI 跑完时弹出桌面通知。

## 令牌

按配置档保存的令牌，可以对应多个账号或组织，存在你操作系统的钥匙串里。Gitcito 也可以直接借用你的 **git credential helper** 里已经有的凭据，所以一个你早就认证过的组织往往完全不需要配置。见[安全与机密](security.md)。
