# 環境チェック

リポジトリとはまったく関係のない失敗もあります。原因はマシンのほうです。プロファイルでの
サインインには古すぎる git、知らないうちに基本モードに落ちたターミナル、workflow ファイルを
push できない GitHub CLI のログイン。どれも後になって、別の作業の途中にあいまいなエラーと
して現れます。**設定 → 環境**(コマンドパレットの *Settings: Environment* でも可)は、
それらを先にチェックします。

[リポジトリのドクター](repo-settings.md) は別の問いに答えます。*このリポジトリ* が
`.gitcito.json` の求めるとおりにここでビルドできるか、です。環境チェックはアプリ自体を
対象とし、どのリポジトリでも同じです。

![設定の環境チェック](../../screenshots/settings-environment.webp)

## チェックする項目

| 行 | 緑の意味 | 黄または赤の意味 |
|----|----------|------------------|
| **Git** | git 2.31 以降が `PATH` にある | 2.31 より古い: [プロファイル](profiles.md)のアカウントが fetch と push でサインインできない。ない: git をインストールするまで何も動かない |
| **Git LFS** | `git lfs` がインストール済み | 未インストール。LFS にファイルを置くリポジトリだけが必要とする |
| **ターミナル** | ネイティブターミナルが読み込まれた | [ターミナル](terminal.md)が基本モードで動作: 色なし、サイズ変更なし、全画面プログラムなし |
| **Credential helper** | git に HTTPS パスワード用の helper がある — グローバル、または特定ホスト向け(`gh auth setup-git` が設定するもの) | helper がなく、Gitcito の外の git が毎回尋ねる。または平文で保存する `store`。[Credential helper](credentials.md) を参照 |
| **GitHub CLI** | `gh` が `workflow` スコープ付きでログイン済み | それなしでログイン: GitHub は `.github/workflows` を変更する push をすべて拒否する |
| **ファイル監視**(Linux) | inotify の上限が 65,536 以上 | 上限が低いと大きなリポジトリをいくつか開いただけで尽き、新しいフォルダーでステータスが更新されなくなる |

当てはまらない行は表示しません。インストールされていない、またはログインしていない
GitHub CLI と、macOS と Windows のファイル監視です。

## 見つかった問題の直し方

修正方法がある場合、行はそれをコピーボタン付きのコマンドとして示します。たとえば
`gh auth refresh -h github.com -s workflow` は足りないスコープを追加し、`sysctl` の 1 行が
inotify の上限を上げます。**このページ自身が何かを実行することはありません。** 修正の
なかには `sudo` が必要なものやグローバル設定を変えるものがあり、実行前に読むのはあなたの
役目です。実行したら **もう一度チェック** を押してください。

## 制限

- アプリ自身のプロセスから見えるものをチェックします。ターミナル内でだけ `PATH` を変える
  シェルのプロファイルがあると、両者が食い違うことがあります。
- GitHub CLI の行は `gh` 自身のログインを反映し、**設定 → 連携** で接続したアカウントでは
  ありません。両者は別の資格情報です。そちらで `workflow` スコープが足りない場合は、拒否
  された push として現れます。
- インストールされているものを報告します。何もインストールや更新はしません。
