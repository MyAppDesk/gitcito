# עורך חיצוני

לקוח Git הוא המקום שבו קוראים קוד; לעתים נדירות הוא המקום שבו מתקנים אותו. הפער
בין לשים לב לבעיה בדיף לבין להחזיק את הסמן על השורה הזו בעורך שלכם הוא חיפוש
קובץ וגלילה — בכל פעם מחדש.

כוונו את Gitcito אל העורך שלכם פעם אחת והפער נסגר: לחיצה ימנית על שורה בתצוגת
הקובץ או ה־blame פותחת אותה שם, באותה שורה.

## בחירת עורך

**הגדרות ← כללי ← עורך חיצוני.** הרשימה הנפתחת מונה את העורכים ש־Gitcito מוצא
במחשב הזה — הוא מחפש קודם את הפקודה של כל עורך, ואז, ב־macOS, את חבילת האפליקציה
ב־`/Applications` וב־`~/Applications`. הסריקה רצה בכל פעם שאתם פותחים את
ההגדרות, ולכן עורך שהותקן לפני חמש דקות מופיע בלי הפעלה מחדש.

מזוהים מהקופסה:

| עורך | הפקודה שהוא מחפש |
|--------|----------------------|
| Visual Studio Code | `code`, `code-insiders` |
| Cursor | `cursor` |
| Windsurf | `windsurf` |
| Zed | `zed` |
| Sublime Text | `subl` |
| סביבות הפיתוח של JetBrains | `idea`, `webstorm`, `pycharm`, `rustrover`, `goland`, `clion`, `rider`, `phpstorm` |
| Xcode | `xed` |

## המגבלה ששווה להכיר

**קפיצה לשורה דורשת את הפקודה של העורך, לא את הסמל שלו.** חבילת `.app` של macOS
מופעלת דרך `open`, שמקבל נתיב ותו לא — ולכן עורך שנמצא רק כחבילה פותח את הקובץ
בראשו, ו־Gitcito אומר זאת מתחת לרשימה הנפתחת במקום להעמיד פנים אחרת.

התיקון הוא בצד של העורך: *Shell Command: Install 'code' command in PATH* של VS
Code, הקישור הסימבולי `subl` של Sublime, *Toolbox ← Settings ← Shell scripts* של
JetBrains. ברגע שהפקודה קיימת, בחרו את העורך שוב והקפיצה לשורה תעבוד.

## היכן הפעולות מופיעות

| מקום | מה זה פותח |
|---------|---------------|
| לשונית המאגר, המאגר בסרגל הצד, שורת המצב | את תיקיית המאגר |
| עץ הקבצים, קבצי קומיט, קבצי סטאש, מלחין הקומיטים | את הקובץ הזה |
| הסמל בקצה השורה בעץ הקבצים | את הקובץ הזה, בלחיצה אחת |
| לחיצה ימנית על שורה בתצוגת ה**קובץ** | את הקובץ, באותה שורה |
| לחיצה ימנית על שורה בתצוגת ה**blame** | את הקובץ, באותה שורה |
| חבילת `.xcodeproj` או אחרת בעץ הקבצים | החבילה, ביישום שמטפל בה |

פעולות שורה מופיעות רק היכן שמספר השורה עדיין אומר משהו: קובץ שמוצג בקומיט ישן,
או blame שהוחזר לרוויזיה מוקדמת יותר, מחזיקים שורות שכבר אינן תואמות למה שנמצא
בדיסק, ולכן Gitcito אינו מציע קפיצה שם במקום לשלוח אתכם למקום הלא נכון.

## פרויקטי Xcode וחבילות אחרות

‏`MyApp.xcodeproj` הוא תיקייה. Git יודע את זה, וגם עץ הקבצים ידע — עד שזה התחיל
להפריע: לפתוח אותו כדי למצוא את `project.pbxproj`, את `project.xcworkspace`
ותיקייה לכל מפתח תחת `xcuserdata` הוא שלוש הקלקות של רעש עבור דבר שממילא לא
התכוונת לערוך ביד.

מעכשיו הם מוצגים עם סמל חבילה, ו**הקלקה על השורה פותחת את החבילה** — בדיוק כמו
הקלקה כפולה ב-Finder. החץ נשאר, כך שבפעם היחידה שבאמת נחוץ לך
‏`project.pbxproj` — כמעט תמיד התנגשות מיזוג — אתה יורד פנימה כמו קודם.

מזוהות: `.xcodeproj`, `.xcworkspace`, `.xcframework`, `.framework`, `.app`,
`.appex`, `.dSYM`, `.playground`, `.xcuserdatad`.

**לא** מזוהות, בכוונה: `.xcassets` ו-`.lproj`. גם הן חבילות, אבל את הקבצים
שבתוכן באמת עורכים, ולכן קיפולן היה עולה יותר ממה שהוא חוסך.

### המגבלות

**את החבילה פותחת המערכת, לא העורך שלך.** ‏`.xcodeproj` שנמסר לעורך טקסט נפתח
כתיקייה מלאה ברשימות מאפיינים, וזה לא מה שרצה מי שהקליק עליו — לכן Gitcito מוסר
אותו למה שמערכת ההפעלה משייכת אליו, שעל Mac עם Xcode מותקן הוא Xcode. בחירת
העורך שלך אינה משתנה, והיא עדיין קובעת לכל קובץ רגיל.

**זו מוסכמת שמות, לא דגל של מערכת הקבצים.** Gitcito מסתכל על הסיומת, ולכן גם
תיקייה שבמקרה קראת לה `notes.app` תקופל, ובלינוקס או בחלונות — שבהן אלה תיקיות
רגילות — הקלקה תפתח את מנהל הקבצים במקום סביבת פיתוח.

## פקודה משלכם

בחרו **פקודה מותאמת אישית** לכל דבר שאינו בטבלה — סקריפט עוטף, משגר פיתוח מרוחק,
עורך טרמינל שמופעל דרך shim משלכם.

| שדה | משמעות |
|-------|---------|
| פקודה | קובץ ההרצה. בלי מעטפת, ולכן בלי `&&`, בלי צינורות ובלי תווים כלליים. |
| שם | איך רשומות התפריט יקראו לו. |
| ארגומנטים לקובץ | תבנית argv, למשל `-g {path}:{line}:{col}` |
| ארגומנטים לתיקייה | תבנית argv, בדרך כלל רק `{path}` |

התבניות מפוצלות לפי רווחים וכל טוקן מוחלף פעם אחת — נתיב עם רווח נשאר ארגומנט
אחד, ושום דבר לא מפוענח שוב אחר כך, ולכן שם קובץ לעולם לא יכול להפוך לתחביר.
ארבעה מצייני מקום: `{path}`, `{line}`, `{col}`, `{repo}`.

מציין מקום בלי ערך לוקח איתו את הדגל שלו: `--line {line} {path}` שרץ בלי שורה
הופך לנתיב בלבד, ולעולם לא ל־`--line` משתלשל שהיה אוכל את שם הקובץ כארגומנט שלו.
תבנית בלי `{line}` בתוכה פשוט אומרת ש־Gitcito לא יציע פעולות מדויקות־שורה לעורך
הזה.

## מה זה לא

זו אינה ההגדרה של [אפליקציית ״פתיחה באמצעות״](repo-settings.md), שמציגה את בורר
המערכת וזוכרת אפליקציה אחת לפתיחת *כל דבר* — תמונה, PDF, תיקייה ב־Finder. העורך
הוא הספציפי מבין השניים, ולכן היכן ששניהם מוגדרים העורך מנצח בסמל שבקצה השורה של
עץ הקבצים; שניהם נשארים ברשימה בתפריט הלחיצה הימנית.

Gitcito לעולם אינו מפעיל את העורך שלכם מעצמו, וסגירת Gitcito לעולם אינה סוגרת
אותו: העורך מופעל מנותק, כתהליך משל עצמו.
