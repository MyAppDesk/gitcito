# ホスティングとプルリクエスト

## 作成

アプリを離れずにプル（またはマージ）リクエストを作成できます。ブランチのドロップ
ダウン、ブランチのコミットからあらかじめ埋められたタイトルと本文、ドラフトの
切り替え、そして GitHub ならレビュアー・ラベル・担当者を作成時にそのまま適用でき
ます。

![プルリクエストの作成](../../screenshots/create-pr.webp)

**GitHub、GitLab、Bitbucket、Azure DevOps** で動作します。4 つすべての未クローズの
PR / MR がサイドバーに並びます。

起点はブランチ比較、グラフ、PR パネルの `+`、あるいはイシュー（`Closes #N` が自動で
入ります）のどこからでも構いません。

## 一覧の中のスタック

互いの上に乗っているプルリクエストは、スタックのアイコン、鎖の着地先ブランチ、件数を持つ
1 行にたたまれます。開けば、鎖が読む順（葉から下のベースへ）で並びます。ベースを見比べて
組み立て直す 4 行の並びではありません。

そのまとまりを決めるものは二つ。プルリクエストが[ネイティブなスタック](stacks.md)に属する
場合は GitHub 自身のスタック番号、そうでなければ ref そのもの — 別のプルリクエストの head
をベースにしているものは、その上に乗っています。二つ目の規則があるおかげで、GitLab・
Bitbucket・Azure DevOps でも同じように働きます。

## レビュー — GitHub と GitLab

| | |
|---|---|
| **会話** | コメントとレビューの状態 |
| **チェック** | CI のチェック実行（GitHub）またはパイプラインジョブ（GitLab）と成功／失敗／保留、ログを開くリンク |
| **表示済みファイル** | ファイルごとの ✓ チェックリストと進捗 |
| **インラインスレッド** | `file:line` ごとにまとめられた行コメントと、返信 |
| **アクション** | コメント、承認、変更要求、そしてマージ／スカッシュ |

レビューの途中で誰かがフォースプッシュしても、[前回から何が変わったか](range-diff.md)
が動いた部分を正確に見せてくれます。

GitLab の違いをはっきり述べておきます。GitLab には単一の「レビューを送信」という
呼び出しがないため、**承認** は承認用エンドポイントを使い、**変更要求** はあなたの
承認を取り消してコメントを投稿します。**リベースマージ** は提供されません。GitLab
はプロジェクトの設定からマージコミットかファストフォワードかを決めるため、マージ
メニューに並ぶのはマージとスカッシュだけです。インラインスレッドはファイルと行を
表示しますが、GitLab の API が返さない周囲の差分ハンクは表示できません。レビューと
マージは **gitlab.com** 上のプロジェクトで動作し、セルフホストのインスタンスはまだ
サポートされていません。Bitbucket と Azure DevOps のレビューは引き続きブラウザーで
開きます。

## イシュー、マイルストーン、リリース — GitHub

イシューを一覧し、専用タブで開けます。本文、コメント、ラベル、担当者、マイルストーン、
Projects v2 のフィールド、クローズ／再オープン、そして **このイシュー用のブランチを
作成**（AI による命名つき）。マイルストーンは進捗とそこに属するイシューを表示し、
リリースは変更履歴ページ付きで閲覧できます。

## 通知 — GitHub

レビュー依頼、メンション、CI の動きまで含めた受信箱全体を、すべてのリポジトリを
横断して表示します。未読／すべての切り替えと既読化つき。ツールバーのベルには未読
バッジが付き、レビューを依頼されたときや CI が終わったときにデスクトップ通知を出す
こともできます。

## トークン

複数アカウントや組織のためのプロファイル単位のトークンを、OS のキーチェーンに保存
します。Gitcito は **git の資格情報ヘルパー** がすでに持っているものを借りることも
できるので、認証済みの組織なら設定が一切要らない場合も少なくありません。
[セキュリティと秘密情報](security.md) を参照してください。
