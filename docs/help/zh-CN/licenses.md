# 开源许可证

Gitcito 构建在九十多个开源包之上，几乎所有包都要求同样的回报：让它们的声明随二进制文件
一起分发。MIT、BSD 和 Apache 在正文里就是这么写的。这个页面就是这些声明所在的地方，这样
由应用本身履行义务，而不是依赖某个需要有人记得复制的文件。

它也是对“我的机器上到底在运行什么”的诚实回答。

## 打开方式

点击状态栏中的**版本号**——会打开**新功能**——然后点击其标题栏中的**许可证**。或者打开
命令面板搜索 *开源许可证*。它会像新功能一样在单独的标签页中打开。

![许可证标签页](../../screenshots/licenses.webp)

| 列 | 含义 |
|----|------|
| 名称 | 包在 npm 上发布的名称 |
| 版本 | 此次构建解析到的确切版本 |
| 徽章 | 包清单中的 SPDX 标识符 |

选中一行即可阅读包附带的完整许可证文本。链接图标会在浏览器中打开项目页面。筛选框同时
匹配包名和许可证标识符，所以输入 `Apache` 会把列表缩小到 Apache 许可的包。

## 涵盖什么，不涵盖什么

列表在构建时由**生产依赖树**生成——即最终进入打包应用的一切，包括你从未直接要求的传递
依赖——外加 Electron 本身。从不分发的构建工具被有意排除。

值得了解的两点限制：

- **有少数包没有附带许可证文件。** 它们只在清单中声明了标识符，别无其他。这些行会如实
  说明，而不是编造文本，因为读不到的许可证不是可以依赖的许可证。
- **标识符是包自己声称的。** Gitcito 只是展示它，并不审核。如果某个包的清单有误，此页面
  也会随之出错。

Gitcito 自身的许可证是 MIT，右上角的徽章会在 GitHub 上打开它。
