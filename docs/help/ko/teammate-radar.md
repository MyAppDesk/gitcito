# 팀원 레이더

당신은 `api.ts` 를 고치고 있어요. 다른 누군가도, 당신이 아직 들여다보지 않은
브랜치에서 같은 파일을 고치고 있고요. 그걸 알게 되는 보통의 방법은 다음 주의 머지
충돌이지만, 레이더의 방법은 오늘의 목록이에요.

모든 것은 당신의 **마지막 페치** 로부터 계산돼요 — 리모트 추적 ref와 메모리 안의
`merge-tree`, 그게 전부예요. 서버도 없고, 팀원들 컴퓨터에서 도는 에이전트도 없고,
어차피 하고 있던 페치 말고는 네트워크도 쓰지 않아요.

![팀원 레이더](../../screenshots/teammate-radar.webp)

## 행 하나가 알려 주는 것

당신의 `HEAD` 에 없는 커밋을 가진 모든 리모트 브랜치에 대해:

| 열 | 뜻 |
|--------|---------|
| 누가 · 언제 | 그 브랜치의 마지막 커미터와, 얼마나 전인지 |
| 커밋 / 파일 | 얼마나 들어오는지, 그리고 몇 개의 파일을 건드리는지 |
| **겹침** | 그중 어떤 파일이 **지금 당신 작업 트리에서 수정 중인지** — 빨간 알약 |
| 위험 | 그 브랜치를 `HEAD` 에 머지하면 충돌할지([충돌 레이더](conflict-radar.md)와 같은 엔진) |

행은 당신과 얼마나 부딪히는지로 정렬돼요. 겹침이 먼저, 그다음이 충돌 예상, 그다음이
최신 순이에요. 행을 펼치면 정확한 파일 목록이 보이고, **비교** 를 누르면 전체 브랜치
비교가 열려요.

## 언제 말을 거는지

페치할 때마다 — 수동이든 자동이든 — 레이더는 조용히 훑어요. 토스트를 띄우는 건
업스트림 커밋이 당신이 수정한 파일을 건드리고, **그리고** 그 집합이 지난번 훑기
이후 실제로 달라졌을 때뿐이에요. 수정 중인 파일이 없으면 잡음도 없어요. 깨끗한
작업 트리는 무엇과도 부딪힐 수 없으니까요.

## 한계

- 마지막 페치가 본 것만 볼 수 있어요. 아직 푸시하지 않은 팀원은 보이지 않아요 —
  이건 ref를 읽는 거지, 마음을 읽는 게 아니에요.
- 겹침은 경로 수준이지 줄 수준이 아니에요. 같은 파일을 건드린다는 건 미리 알리는
  신호일 뿐, 충돌의 증거는 아니에요. **위험** 열이 줄 수준의 답이지만, 커밋된
  상태끼리만 비교해요.
- 45일쯤 움직임이 없던 브랜치는 건너뛰고, 최근에 움직인 30개만 스캔해요.
