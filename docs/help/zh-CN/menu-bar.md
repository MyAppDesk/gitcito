# 菜单栏

菜单栏回答了一个别处都答不好的问题：*这个应用到底能做什么？*
[命令面板](search.md)在你已经知道要找什么时更快，[速查表](keyboard.md)列出了按键——
但这两者都不是用来浏览的。菜单是。

菜单里的每一项也都能在窗口内部找到。没有任何功能只存在于菜单里，这是刻意的：
只活在菜单里的功能，就是 Windows 和 Linux 用户没有的功能。

## 各菜单的内容

| 菜单 | 内容 |
|---|---|
| **Gitcito** | 关于、检查更新、[设置](repo-settings.md)，以及标准的隐藏与退出项 |
| **文件** | 新建标签页、打开或[克隆](cloning.md)仓库、打开最近使用、关闭与重新打开标签页 |
| **编辑** | 剪切、拷贝、粘贴、撤销——键盘本来就在做的文本编辑——外加[代码搜索](search.md) |
| **显示** | 命令面板、侧边栏与右侧面板开关、[终端](terminal.md)、[mission control](mission-control.md)、[保险库](vault.md)、缩放 |
| **仓库** | Fetch、pull、push、提交、贮藏、新建分支、[pull request](hosting.md)、撤销、在 Finder 中显示、仓库设置 |
| **窗口** | 最小化、缩放、全部置于顶层 |
| **帮助** | 本手册、速查表、更新内容、许可证、报告问题 |

当前标签页不是 git 仓库时，仓库菜单整体变灰；没有可撤销的操作时，**撤销**变灰——
菜单本身就是一份可读的摘要，说明此刻应用允许你做什么。

## 显示快捷键，而不是抢走它

每一项旁边显示的按键，就是你实际绑定的按键。在设置里重新绑定 <kbd>⌘K</kbd>，
显示菜单就会照实写出来。

这之所以可行，是因为菜单只*显示*这些组合而不占用它们：键盘处理仍由 Gitcito 自己负责，
这也正是同一个快捷键能根据光标所在位置表现不同的原因。唯一无法这样展示的，
是并不属于 Gitcito 的快捷键——<kbd>⌘F</kbd> 属于你正在阅读的文件或差异，
所以没有任何菜单项去占用它。

## 限制

- **仅限 macOS。** 在 Windows 和 Linux 上窗口是无边框的——标题栏由 Gitcito 自己绘制，
  菜单栏无处安放。那两个平台通过[命令面板](search.md)和[键盘快捷键](keyboard.md)
  得到同样的命令。
- **重新载入和开发者工具只在开发版本中出现。** 重新载入会丢弃每个已打开标签页的状态，
  发布版本不该把它摆在“缩放”旁边。
- **打开最近使用最多列出十个仓库**，按最近使用排序，与[欢迎界面](getting-started.md)
  用的是同一份列表。
- **重新打开已关闭标签页永远不会变灰。** 已关闭标签页的栈只在本次会话内存在，
  菜单看不到它；在没有可恢复项时选择它不会有任何反应。
