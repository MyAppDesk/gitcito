# 파일 속성

`.gitattributes`는 git에서 가치가 가장 높으면서도 거의 아무도 쓰지 않는
파일이에요. 저장소가 **자기 내용물에 대해 git에게 가르치는** 방법이거든요. 어떤
파일이 바이너리인지, 어떤 파일이 충돌하는 대신 이어 붙여야 하는지, 어떤 파일이
아카이브에는 절대 들어가지 않는지, 모두가 어떤 줄바꿈 문자를 받게 되는지.

중요한 점: 이 파일은 커밋돼요. 여러분이 추가한 규칙 하나가 클론하는 모든
사람에게, 모든 OS에서, 영원히 문제를 해결해 줘요. 자기 설정에 넣은 항목이
자기에게만 문제를 풀어 주고 동료들은 알아서 고생하며 발견하게 두는 것과는
다르죠.

`⌘K` → **파일 속성**.

![저장소가 이미 지니고 있는 규칙, 프리셋, 경로 검사기와 차이 드라이버](../../screenshots/attributes.webp)

## 각 규칙이 하는 일

| 속성 | 해결하는 문제 |
|-----------|-------|
| `text=auto eol=lf` | 누가 체크아웃했느냐에 따라 뒤바뀌는 줄바꿈 문자 |
| `binary` | git이 PSD, DOCX, 컴파일된 자산의 차이를 내거나 3-way 머지하려 드는 것 |
| `merge=union` | 모두가 덧붙이고, 모두가 충돌하는 변경 기록 |
| `-merge` | 3-way 머지가 말이 안 되는 결과를 내는 파일 — 잠금 파일, 생성된 코드 |
| `export-ignore` | 릴리스 tarball 안에 실려 나가는 CI 설정과 픽스처 |
| `diff=<driver>` | 변환기만 있으면 *읽을 수 있는* 형식인데도 읽을 수 없는 차이 |
| `filter=lfs` | [LFS](lfs-sparse.md)로 저장되는 큰 파일 |
| `linguist-vendored` | 언어 통계에서 여러분 것으로 계산되는 벤더링된 코드 |

`binary`는 `-diff -merge -text`의 줄임말이에요. "이 파일에 대해서는 추측을
그만하라"는 세 가지 대답을 한 단어에 담은 것이죠.

## 편집하기

프리셋은 패턴과 그 속성을 채워 넣어요. 추가하기 전에 패턴을 손보세요 —
`CHANGELOG.md`는 제안이지, 여러분 프로젝트에 대한 규칙이 아니에요.

**편집은 외과적이에요.** 이미 규칙이 있는 패턴에 규칙을 추가하면, 나중에 나온다는
이유로 이기는 두 번째 규칙을 덧붙이는 대신 그 줄을 제자리에서 다시 써요. 파일
안의 주석은 손대지 않고 살아남아요. 규칙 옆에 적힌 "왜"가 보통 규칙 자체보다
값어치가 크기 때문이에요.

저장할 때마다 평범한 Gitcito 동작이 일어나요. 토스트가 뜨고, **되돌리기**가
파일을 원래 상태 그대로 복원해요.

**저장소에는 속성 파일이 여러 개 있을 수 있어요.** 루트에 하나, 어느
하위 디렉터리에나 하나씩, 그리고 절대 커밋되지 않고 여러분 컴퓨터에서만
적용되는 비공개 `.git/info/attributes` — 프로젝트가 아니라 여러분에 관한 규칙을
두기에 알맞은 자리예요. Gitcito는 그것들을 모두 나열하고 어느 것이 어느
것인지 알려 줘요.

## 어떤 경로에 무엇이 적용되나요?

규칙은 여러 파일에서 오고, 더 구체적인 쪽이 이기며, 그것들을 읽어서 답을 알아내는
일은 짐작에 가까워요. **어떤 경로에 무엇이 적용되나요?**는 `git check-attr`을
실행해서 git 자신이 내린 결론을 보여 줘요. 유일하게 의미 있는 답이죠.

## 차이 드라이버: Word 문서를 읽을 수 있게 만들기

`.docx`는 zip이에요. `.pdf`는 압축된 객체 그래프예요. git은 그것들을 있는
그대로 — 잡음으로 — 비교하므로, 문서 자체는 읽을 수 있는데도 문서의 히스토리는
읽을 수 없어요.

**차이 드라이버**는 `textconv`로 이 문제를 해결해요. *차이를 낼 때만* 파일을
텍스트로 바꿔 주는 명령이죠. 작업 트리에 있는 파일은 건드리지 않아요. git은
변환된 텍스트를 비교할 뿐이에요.

두 부분이 있고, 둘 다 필요해요.

1. git 설정의 `diff.<name>.textconv` — 변환 명령.
2. `.gitattributes`의 `*.docx diff=<name>` — 어떤 파일에 적용할지.

여기 있는 버튼들이 둘을 한 번에 해 줘요. Gitcito는 **이 변환기들을 하나도
동봉하지 않으며** 그런 척하지도 않아요. PATH를 확인해서 실제로 설치된 것만
제공하고, 나머지는 필요한 실행 파일 이름과 함께 흐리게 표시해요.

| 드라이버 | 필요한 것 | 얻는 것 |
|--------|-------|-----------|
| `word` | `pandoc` | `.docx`의 문장 단위 차이 |
| `pdf` | `pdftotext` (poppler) | `.pdf`의 텍스트 차이 |
| `excel` | `xlsx2csv` | 스프레드시트의 행 단위 차이 |
| `exif` | `exiftool` | 픽셀이 불투명할 때, 이미지에 대해 무엇이 바뀌었는지 |
| `json` | `jq` | 키 순서가 정렬된, 안정적인 JSON 차이 |

변환기 쪽은 저장소가 아니라 **여러분의** 설정에 살아요. git은 클론이 건네주는
명령을 실행하지 않으니까요. 지켜 둘 만한 보안 특성이에요. 그래서 클론한 동료는
`diff=word` 규칙은 받지만, pandoc을 설치하기 전까지는 예전의 읽을 수 없는 차이를
보게 돼요. README에 그 사실을 적어 두세요.

## 알아 둘 만한 한계

- **clean/smudge 필터는 여기서 제공하지 않아요.** `filter=<name>` 규칙은 손으로
  적을 수 있지만, Gitcito는 그 명령을 설정해 주지 않아요. 필터는 일치하는 모든
  파일의 모든 체크아웃마다 실행되고, 잘못된 필터는 작업 트리를 조용히 망가뜨리기
  때문이에요.
- **`text=auto`는 무엇이 커밋되는지를 바꿔요.** 들어오는 길에 줄바꿈 문자를
  정규화하니까요. 이미 존재하는 저장소라면, 추가한 다음 의도적으로
  `git add --renormalize .`를 실행하고 그것만을 위한 커밋 하나로 남기세요.
- **속성은 소급 적용되지 않아요.** 오늘 파일을 `binary`로 표시한다고 해서 그
  파일의 과거 차이가 저장된 방식이 바뀌지는 않아요. 지금부터 git이 그 파일을
  어떻게 다루는지가 바뀔 뿐이에요.
- **규칙은 그 파일이 보이는 곳에서만 효력이 있어요.** `design/.gitattributes`의
  규칙은 `src/`에 대해서는 아무 말도 하지 않아요.
- Gitcito는 파일을 통째로 쓰므로 손으로 서식을 맞춘 파일은 그 서식 그대로
  돌아와요. 다만 Gitcito가 다시 쓴 규칙은 git의 표준 형태인
  `pattern attr attr` 간격으로 재정렬돼요.
