# 안전한 공유

새 기기 — 또는 새 팀 동료 — 를 준비한다는 건 보통 모든 걸 처음부터 다시 입력한다는
뜻이에요. 안전한 공유는 그 대신 그것들을 암호화된 `.gitcito` 파일 하나로 묶어요.
Gitcito의 팀 기능에는 **백엔드가 없어서**, 이 파일이 *곧* 운송 수단이에요. 평소
파일을 보내던 방법 그대로 보내세요. 암호는 따로 전달하고요.

![저장소 하나의 설정을 암호화된 번들로 내보내기](../../screenshots/secure-share.webp)

![작업 공간 전체를 같은 방식으로 내보내기](../../screenshots/secure-workspace.webp)

## 담을 수 있는 것

| 섹션 | 내용 |
|---|---|
| **금고** | 전역 금고의 비밀 (저장소별 금고 항목은 그대로 남아요) |
| **저장소 파일** | 추적되지 않는 설정 파일과 비밀 파일 — 가져올 때 같은 상대 경로에 다시 만들어져요 |
| **작업 공간 구조** | 탭 배치 그 자체 — 그룹, 색, 순서 — 저장소는 원격 URL로만 참조되고, 여러분의 로컬 경로는 절대 쓰이지 않아요 |
| **커밋 노트** | 저장소의 `refs/notes/commits` — 가져올 때 적용되고, 어떤 원격에도 쓰기 권한이 필요 없어요 |

비밀은 **체크 상자를 켰을 때만** 들어가요. 그 체크가 없는 번들에는 자격 증명이
하나도 들어 있지 않아요. 앱 설정은 번들로 옮겨지지 않아요 — 설정에는 설정 화면에
따로 마련된 일반 JSON 내보내기가 있거든요.

## 가져오기

가져오기 화면은 무엇이든 적용하기 **전에** 안에 무엇이 들었는지 섹션별로
보여주고, 저장소는 이미 가지고 있는 것과 대조돼요 — 먼저 원격 URL로, 그다음
폴더로 — 그래서 가져오기가 세상을 다시 클론하는 일은 없어요.

**작업 공간 구조** 섹션은 이미 가지고 있는 저장소들로 작업 공간을 다시 만들어요.
없는 저장소는 원격 주소와 함께 목록으로 보여 주니, 먼저 클론한 다음 다시 가져오면
돼요 — 여기서 Gitcito가 여러분 대신 클론해 주는 일은 절대 없어요. **커밋 노트**
섹션은 무엇이 들어올지 미리 보여 줘요 — 새 노트, 동일한 노트, 서로 다른 노트, 또는
가지고 있지 않은 커밋에 달린 노트 — 그리고 서로 다른 노트는 **덮어쓰기**를 체크했을
때만 교체돼요. 갈라진 노트를 머지하지는 않아요.
