# 堆叠分支

一个堆叠就是一串分支，其中每一个都建立在下面那个之上：`main → api → ui`。评审三个小 PR，好过评审一个巨大的。

![一个分支堆叠](../../screenshots/branch-stack.webp)

Gitcito 自上而下画出这个堆栈，一直画到它最终落上去的主干。每一层显示自己的提交数、
**它的 PR 会指向哪里**——下面那一层，最底下那层则是主干——以及提交之后的 PR 编号，
点一下就能打开。

## 搭一个堆栈

| 这样做 | 结果 |
|--------|------|
| **添加层** | 在最上面那层之上创建分支并切过去。这就是 `gh stack add`，只是把必填参数换成了选择器。 |
| 在任意层上**在其上添加** | 一样，但是在堆栈*中间*：原本压在那一层上的东西会被重新指到新分支，于是链条保持顺序、多出一层。什么都不用重放——新分支就建在父分支的尖端。 |
| **加入已有分支** | 你手上已有的分支从顶部加入堆栈。适合一开始按普通方式做、后来才发现这其实是个堆栈的情况。 |

所有分支输入框都支持**边打边筛**：输入即过滤，↑/↓ 和 Enter 选中，而且你打的东西
即使不在列表里也算数——所以 `origin/main` 这样的远端引用同样可以当底座。

## 重新排序

某一层上的 **↑ / ↓** 箭头会把它和邻居对调。这不是改元数据：链条会被重新连接并重放，
让每一层自己的提交落到新的基底上。这一步可以撤销（<kbd>⌘Z</kbd>）——撤销是把旧顺序
重放一遍，不是把旧提交复活。

因为重新排序就是一连串 rebase，所以它和 restack 一样会**冲突**。Gitcito 在第一个
冲突处停下并把冲突界面交给你；它下面的那些层已经挪好了。

## 指向别处

某一层上的**设置父级**会打开同一个选择器：选另一个分支，这一层的连接就挪过去。底部的
**基底**那一行对主干做同样的事——换掉它，整个堆栈就重新连到新主干上并重放。

## 全部推送

**全部推送**用 `--force-with-lease` 推送每一层，然后就停下——相当于什么都不打开的
`gh stack push`。下面的**把堆栈提交为 PR**会做同样的推送，再做 PR 那部分工作；当你
只想让分支上远端、还不打算送审时，用**全部推送**。

## 把堆叠提交为链式 PR

**将堆叠提交为 PR** 一键完成那些堆叠工具收费才肯做的事：

1. 用 `--force-with-lease` 推送每一层（新分支怎样都能接受，重新堆叠过的分支则少不了它）。
2. 为每个还没有 PR 的层开一个 PR——各自**以父分支为基底**，而不是 `main`，因此每个评审只显示它自己的提交。标题和描述取自该层自己的提交。
3. 为基底已经漂移的现有 PR 重定目标。
4. 在每个 PR 正文里写入一段**堆叠导航**，让任何一层的评审者都能看到整条链，以及这个 PR 在链中的位置。

这个操作是**幂等**的：每次重新堆叠、新增一层或合并 PR 之后按它，结果都会收敛——什么都不会重复，只有漂移的部分会被更新。

最底部的 PR **合并**之后，同一个按钮还会替它善后：已合并那层的子分支会改挂到主干上，那一层被取消跟踪，它的本地分支被删除（很安全——主干可证明地包含了它），整条链重新堆叠，剩下的每个 PR 都会重定目标。自下而上合并，按一下提交，如此往复。

## 重新堆叠

当下层的某个分支变了——比如你处理了 `api` 上的评审意见——它上面的每个分支现在都建立在错误的基底上。**重新堆叠**会用 `rebase --onto` 对整条链做级联变基，这样父分支的重写就不会把提交重复塞进它的子分支里。重新堆叠之后再按一次**提交**：它会强制推送被重写的层，PR 会就地更新。

## 限制

- 提交目前**仅支持 GitHub**（创建在四个托管平台上都能用，但重定目标和正文更新需要 GitHub API）。
- 底部合并后的清理通过祖先关系识别 merge 和 rebase 式合并，通过询问 GitHub 该分支的 PR 是否已落地来识别 **squash** 合并——所以只要有 GitHub 令牌，每种合并方式都能被清理。在其他托管平台上，或者没有令牌时，经 squash 合并的那层仍需手动取消跟踪。另外记得先抓取（fetch）——祖先关系检查读到的主干是你上次抓取时的状态。
- PR 正文里的堆叠段落维护在隐藏标记之间——你写在它上方的描述会原样保留。
- 重新排序和换主干会在它们碰到的每一层上**改写历史**。分支是你自己的，没推过的
  层不花什么代价，但已经在评审中的层会在下一次提交时挨一次强制推送。
- 一层一次只挪一格。两次对调就是两次 rebase，半路停下仍是个看得懂的状态；一拖就
  落到三格开外则不是。

## 这些链接存在哪儿

父级链接存在 **git config** 里，所以它们跟着仓库走，而且重新克隆之后依然健在。没有任何东西寄存在某个服务上。
