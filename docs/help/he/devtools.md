# Flutter DevTools

ל‑DevTools כבר יש תצוגת רשת, ציר זמן, מפקח ווידג'טים ומנתח זיכרון — והוא עצמו
אפליקציית Flutter web שמוגשת מהמחשב שלכם. לכן Gitcito לא בונה שום דבר מזה מחדש,
וגם לא מדבר בעצמו עם Dart VM Service: הוא מבחין בכתובת ומטמיע אותה.

![‏DevTools פתוח בלשונית של Gitcito](../../screenshots/devtools.webp)

ברגע ששירות ה‑VM עולה, ‏`flutter run` מדפיס את השורה:

```
The Flutter DevTools debugger and profiler on iPhone 16 Pro is available at:
http://127.0.0.1:9100?uri=http://127.0.0.1:53412/uJ8k=/
```

הפעלת ההרצה עוקבת אחרי הפלט של עצמה בשביל השורה הזאת, ובשורת הניפוי מופיע כפתור.
לחיצה פותחת את DevTools בלשונית משלו, אחת לכל הפעלה — שתי אפליקציות שרצות יחד הן
שני DevTools.

**הפעלה חוזרת חמה מפרסמת כתובת חדשה**, והלשונית עוקבת אחריה כל עוד ההפעלה חיה.
כשההפעלה נגמרת, הלשונית שומרת את הכתובת האחרונה, שבדרך כלל כבר מתה: סגרו אותה
ופתחו את DevTools מההרצה החדשה.

## מה מותר לו

התצוגה המוטמעת מהלכת ברצועה קצרה, כי האפליקציה הזאת מחזיקה אישורי גישה:

- **לולאה מקומית בלבד.** ‏`127.0.0.1`, ‏`localhost`, ‏`::1`. חיבור לכל כתובת אחרת
  נדחה, וגם הפניה אליה.
- **בלי preload, בלי node integration, עם בידוד הקשר.** לדף אין שום גשר אל
  Gitcito.
- **קישורים נפתחים בדפדפן האמיתי שלכם**, בחלון רגיל, לא בתוך הלוח.

## המגבלות

- **זה DevTools, לא משהו שלנו.** מה שהגרסה הזאת יודעת לעשות — הלוח עושה; מה שהיא
  לא יודעת, גם אנחנו לא. אין תצוגת רשת בטעם Gitcito.
- **רק Flutter מכריז על עצמו כך.** תוכנית Dart רגילה מדפיסה כתובת של שירות VM אבל
  לא כתובת DevTools, ולכן לא מופיע כפתור.
- **לוח ריק פירושו שהאפליקציה נעצרה.** את DevTools מגישה *האפליקציה שרצה*;
  כשהיא מסתיימת, הכתובת שלה מפסיקה לענות.
