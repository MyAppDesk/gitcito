# 접근성

Gitcito는 마우스 없이도 다룰 수 있고 스크린 리더로도 읽히는 것을 목표로 해요.
이 페이지는 그게 구체적으로 무슨 뜻인지 — 그리고 한계가 어디인지 — 말해요.

## 키보드

- **탭, 사이드바 행, 파일 목록, 도구 모음 메뉴**는 초점을 받을 수 있고
  Enter나 Space로 실행돼요. 분할 버튼(pull/push/stash)은 드롭다운 화살표를
  별도의 초점 가능한 컨트롤로 제공해요.
- **커밋 그래프**는 초점 정거장이 하나예요. 초점을 준 뒤 위/아래(또는 j/k)로
  히스토리를 훑으세요. 선택된 커밋은 제목, 작성자, 위치와 함께 읽어 줘요.
  Shift+F10(또는 메뉴 키)이 선택된 커밋의 컨텍스트 메뉴를 열어요.
- **컨텍스트 메뉴**는 초점이 잡힌 채로 열려요. 화살표 키로 이동하고, Enter로
  실행하고, ArrowRight/ArrowLeft로 하위 메뉴에 들어가고 나오고, Escape로
  닫아요.
- **대화 상자**는 Tab을 안에 가두고, 닫힐 때 원래 있던 곳으로 초점을
  돌려주고, Escape로 닫혀요.
- **명령 팔레트**(Cmd/Ctrl+K)는 콤보박스예요. 입력하는 동안에도, 화살표로
  훑는 동안에도 결과를 읽어 줘요.

## 스크린 리더

- 모든 대화 상자는 제목과 함께 안내돼요. 토스트 — 앱의 피드백 채널 — 는
  라이브 영역이에요. 성공은 정중하게 알리고, 오류는 끼어들어요.
- 진행 상황(클론, 업데이트 다운로드)은 백분율이 있는 진행 표시줄로 노출되고,
  작업 중 상태("가져오는 중…")는 스스로 안내돼요.
- 파일 상태는 색깔 있는 기호로만 보여 주는 게 아니라 말로도 전해요("추가됨",
  "수정됨", "충돌").
- 창은 랜드마크(banner, main, 사이드바, 상태 표시줄)로 구조화되어 있어서
  랜드마크 탐색이 동작해요.

## 한계, 있는 그대로

- **터미널**은 xterm.js라서 그 스크린 리더 사정을 그대로 물려받는데, 그
  사정이 약해요. 눈으로 보는 사용자를 위한 표면으로 여기세요. 터미널이
  제공하는 모든 git 작업은 UI 액션으로도 존재해요.
- **Cosmos(3D 히스토리), 커밋 그래프의 레인, 이미지 diff**는 본질적으로
  시각적이에요. 그 뒤에 있는 데이터 — 커밋 목록, 파일 목록 — 는 접근
  가능하지만, 그림 자체는 아니에요.
- **드래그 앤 드롭**(인터랙티브 리베이스 단계 재정렬, 병합하려고 브랜치
  끌기)은 표시된 곳에서는 포인터 전용이에요. 드래그 동작마다 메뉴나 버튼으로
  된 대체 수단이 있어요.
- 이 페이지 뒤의 점검은 macOS의 VoiceOver로 했어요. Windows의 NVDA/JAWS도
  똑같이 동작해야 하지만 실전 검증은 아직이에요 — 제보는
  [issues](https://github.com/MyAppDesk/gitcito/issues)로 환영해요.

## 관련 설정

**동작 줄이기**는 OS 설정을 따라요 — 애니메이션이 즉시 전환으로 바뀌어요.
테마 대비는 [설정 → 겉모습](themes.md)에서 테마별로 조절할 수 있어요.
