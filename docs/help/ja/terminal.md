# 統合ターミナル

コマンドランナーではなく、本物の PTY（xterm + node-pty）です。あなたのシェル、あなたの
プロンプト、あなたのエイリアスがそのまま使えます。

![統合ターミナル](../../screenshots/terminal.webp)

- **リポジトリごとに複数のタブ**。それぞれそのリポジトリのフォルダで始まります。
- グラフの **下** にドッキングするか、**右側の列** として置けます。ペインはサイズを
  覚えています。
- ターミナルの表示状態はリポジトリごとです。一度も開いていないタブに切り替えても、
  閉じたままになります。
- タブは、その中で動いているものの名前を自分で名乗ります。
- ターミナルの一覧を畳むと **レール** に縮みます。ターミナルごとにアイコンが 1 つ
  （分割されたターミナルは小さなパネル図を出します）並び、クリックで切り替え、右クリック
  でいつもの名前変更・分割・終了のメニューが出ます。
- リストで**ターミナルを別のターミナルにドラッグ**すると、分割グループに統合
  されます。各ターミナルはペインとして自分の名前を保ち、グループは新しい番号付き
  の名前になります。

![1 つのターミナルグループの中で左右に分割された 2 つのパネル](../../screenshots/terminal-split.webp)

## キー

| キー | 動作 |
|---|---|
| <kbd>⌃`</kbd> | ターミナルの表示・非表示 — どのプラットフォームでも物理的な Control キー |
| <kbd>⌘T</kbd> / <kbd>Ctrl+T</kbd> | ターミナルにフォーカスがあるときに新しいターミナル |
| <kbd>⌘W</kbd> / <kbd>Ctrl+W</kbd> | フォーカス中のターミナルを閉じる。最後の 1 つを閉じるとパネルが隠れる |
| <kbd>Ctrl+Shift+C</kbd> | 選択範囲をコピー。選択があるあいだは単独の <kbd>Ctrl+C</kbd> もコピーし、選択がなければ SIGINT のまま |
| <kbd>Ctrl+V</kbd> / <kbd>Ctrl+Shift+V</kbd> / <kbd>Shift+Ins</kbd> | クリップボードから貼り付け |
| 右クリック | 選択範囲をコピー。何も選択していなければ貼り付け |

最初の 2 つは意図的にターミナル内だけで効きます。ターミナルの外では、これまでどおり
[ワークスペースのタブ](workspaces.md)を開閉します。macOS では「編集」メニューの
コピー/ペーストも同じように動きます。

## スクリプトの候補

`npm run `(または `pnpm`、`yarn`、`bun run`)と入力すると、カーソル位置にプロジェクトの
スクリプト一覧が現れ、入力に合わせて絞り込まれます。`npm run loc` で `LOCAL_SERVER` が
見つかります。各名前には実行されるコマンドが表示されます。

| キー | 動作 |
|------|------|
| **Tab** | 選択したスクリプトを補完 |
| **↑ / ↓** | 別の候補を選ぶ |
| **Esc** | 次に入力するまで一覧を閉じる |

ほかのコマンドにもそれぞれの一覧があります:

| 入力 | 一覧 | 読み取り元 |
|---|---|-----|
| `composer run ` | Composer のスクリプト | 最も近い `composer.json` |
| `make ` | Makefile のターゲット。ターゲットの後の `## テキスト` が説明になる | 現在のディレクトリの `Makefile`(`make` と同じ読み方) |
| `git checkout `、`switch`、`merge`、`rebase` | ローカルブランチ、続いてリモートブランチを短い名前で | シェルがいるリポジトリ |

変数やパターン(`%.o`)で組み立てた Makefile のターゲットは表示されません。
`git checkout -b` には一覧が出ません。新しいブランチに名前を付けるコマンドだからです。

スクリプトはシェルの**現在の**ディレクトリに最も近い `package.json` から読みます。
`cd frontend` の後ならフロントエンドのものが出ます。入力した文字で始まる名前が先、
それを含む名前が後に並びます。

一覧が知っているのは、最後の Enter 以降に入力したキーだけです。↑ でコマンドを呼び戻す、
カーソルを動かす、シェル自身の Tab 補完を使う、といった操作は一覧から見えないところで
行を変えるため、間違ったものを補完するより、次の Enter まで黙っています。Windows では
現在のディレクトリを読み取れないため、一覧はターミナルを開いたフォルダーに従います。

## PATH について

シェルは Terminal.app や iTerm と同じく **ログインシェル**として起動するので、
`~/.zprofile`、`~/.zlogin`、`~/.bash_profile` がすべて読み込まれます。バージョン
管理ツールや `brew shellenv` は通常そこに自分を登録するため、これは重要です。
ターミナルで動く `fvm`、`nvm`、`pyenv` のようなツールは、ここでも同じように動きます。

Gitcito は起動時にログインシェルへ本当の `PATH` を問い合わせ、起動するすべての
プロセスにマージします。Dock から起動した GUI アプリはほとんど何も引き継がない
からです。それでもコマンドが見つからない場合は、それが対話シェルだけでなく
ログインシェルの `PATH` に入っているか確認してください。

ここで実行したものは Gitcito 自身のロックからは見えないので、手で打った長い
`git rebase` と UI でのクリックはやはり衝突し得ます。ターミナルが何かを変えたときは、
アプリがディスクから読み直します。

## シェル、テーマと Oh My Posh

Windows では、設定 → レイアウトで新しいターミナルが起動するシェルを選びます —
PowerShell、PowerShell Core(`pwsh`)、`cmd`、Git Bash、WSL、または任意の実行ファイル。
ターミナルの見た目(テーマ、フォントサイズ、フォントファミリー)は設定 → テーマ →
ターミナルテーマにあり、すべてのセッションにすぐ反映されます。

[Oh My Posh](https://ohmyposh.dev) がインストールされていれば、このセクションは
`%POSH_THEMES_PATH%` にあるすべての `*.omp.json` をライブプレビュー付きで一覧します。
選ぶと新しいターミナルに `POSH_THEME` として渡されるので、プロファイルに素の
`oh-my-posh init pwsh` があればそれが使われます。任意の `.omp.json` のパスも指定できます。
欄を「既定」のままにすると、シェルやプロファイル、グローバルな `POSH_THEME` がすでに
設定しているものが保たれます。開いているセッションは作成時のテーマのままです — 新しい
テーマを適用するにはターミナルを閉じて開き直してください。プロンプトのグリフには、
ターミナルのフォントファミリーに Nerd Font(例: `CaskaydiaMono Nerd Font`)が必要です。
ないとアイコンが四角で表示されます。

速度について: Oh My Posh はプロンプトごとにバイナリを 1 回実行します — Windows で
およそ 100〜200 ms、大きなリポジトリで git セグメントのあるテーマならさらに長く — これは
Gitcito の遅れではなく、各プロンプト前の短い間として感じられます。git セグメントのない
テーマが最速です。PowerShell の予測表示スタイルも影響します。
`-PredictionViewStyle InlineView` はキー入力ごとに小さな領域を描き直し、`ListView` は
ブロック全体を描き直します。
