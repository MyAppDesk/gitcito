# コンフリクトレーダー

ブランチがコンフリクトすると知るためにマージしてみるのは、質問の仕方として高くつ
きます。レーダーは先に答えます。

Gitcito は、あなたが選んだベースに対してすべてのブランチを **オブジェクトデータ
ベースのなかで** マージします（`git merge-tree --write-tree`）。チェックアウトなし、
インデックスの変更なし、作業ツリーの変更なし、あとで片付けるものもなし。コミットし
ていない作業は、スキャンが走っているあいだもそのままの場所にいられます。

![レーダー。ブランチごとに 1 つの判定](../../screenshots/conflict-radar.webp)

![ブランチを順にスキャンし、そのあと取り合いになっているファイルを開く](../../screenshots/clip-conflict-radar.webp)

## 使い方

ツールメニュー、<kbd>⌘K</kbd> → *コンフリクトレーダー* から開くか、ブランチを右
クリックして **その** ブランチに対してすべてをスキャンします。

開いた瞬間に、現在のブランチをベースとしてスキャンを始めます。

| 判定 | 意味 |
|---|---|
| **コンフリクトします** | マージには手が要ります。正確なパスが一覧されます。 |
| **きれいにマージできます** | 揉めずに適用できます。 |
| **すでにマージ済み** | ベースがすでに含んでいます — マージするものはありません。 |
| **マージできませんでした** | git が拒否しました。無関係な履歴、存在しない ref。理由が表示されます。 |

ブランチは悪い順に並び、そのなかでも最悪のもの — もっとも多くのファイルに触れるも
の — がいちばん上に来ます。

## 取り合いになっているファイル

その下の **取り合いになっているファイル** は、いくつのブランチがそのパスを書き換え
ているかで順位を付けます。1 つのファイルを 2 つのブランチが取り合っているなら、いま
話し合うべきことです。5 つなら設計の問題です。

## スキャンのあと

サイドバーのブランチ行に色付きのドットが付きます。赤はコンフリクトする、緑はきれい、
琥珀色は git が拒否したブランチです。ベースがすでに含んでいるブランチにはドットが付
きません — すでにマージ済みのもの全部に灰色のドットが並んでも、ただのノイズだから
です。

> スキャンは何も変えません。`git status` はクリーンのままで、HEAD も動きません。
