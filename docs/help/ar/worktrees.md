# أشجار العمل والوحدات الفرعية

## أشجار العمل

شجرة العمل هي سحب ثانٍ للمستودع نفسه، في مجلد خاص بها — كي تنظر إلى `main`
بينما يبقى `feature/x` تمامًا كما تركته، بلا إخفاء للتغييرات.

- أنشئ أشجار العمل واحذفها من الشريط الجانبي. **انقر نقرًا مزدوجًا** على واحدة
  لتفتحها في تبويب خاص بها؛ والنقر بالزر الأيمن يعطيك *فتح شجرة العمل* و*إظهار
  في المجلد* والإزالة.
- انقر بالزر الأيمن على أي فرع محلي ← **افتح في شجرة عمل** كي تُنشئ واحدة في
  مجلد شقيق وتفتحها كتبويب.
- لا يعيش الفرع إلا في شجرة عمل واحدة في المرة، لذا فسحب فرع تحمله شجرة عمل
  أخرى لا يمكن أن ينجح — إذ يرفض git قائلًا *already used by worktree at …*.
  وGitcito يأخذك إلى هناك بدلًا من ذلك: تقرأ قائمة الفرع *الانتقال إلى `x` في
  شجرة عملها*، والنقر المزدوج على السطر يفتح تبويب تلك الشجرة بدل أن يفشل.

### العناية بشجرات العمل

من السهل نسيان شجرة عمل أُنشئت الشهر الماضي، وتأتي الأسئلة عند التنظيف: هل فيها عمل؟ هل ما زال ذلك المجلد موجودًا؟ كل صف يجيب عنها قبل أن تضطر إلى السؤال.

| في الصف | المعنى |
|---|---|
| **●3** | ثلاثة ملفات بها تغييرات غير مُودعة في شجرة العمل تلك |
| **↑2 ↓1** | فرعها متقدم بإيداعين ومتأخر بإيداع واحد عن الـ upstream |
| 🔒 | مقفلة — مرّر المؤشر لرؤية السبب المذكور عند القفل |
| **مفقودة**، والاسم مشطوب | المجلد لم يعد موجودًا؛ لم يبقَ في git سوى سجلّه |

تُقرأ الأرقام عند فتح القسم، وعند تغيّر إيداع شجرة العمل تلك، وعند استعادة النافذة للتركيز — لا مع كل تحديث، لأن كل رقم يعني تشغيل `git status` داخل مجلد آخر.

انقر بزر الفأرة الأيمن على صف من أجل:

| الإجراء | ما يفعله |
|---|---|
| **قفل شجرة العمل** | يمنع git (وأي عميل آخر) من تنظيفها أو نقلها أو إزالتها. اكتب سببًا — *على القرص الخارجي* — فيظهر على القفل. لشجرات العمل على وسائط ليست موصولة دائمًا. |
| **إلغاء قفل شجرة العمل** | العكس. التراجع يقفلها من جديد بالسبب نفسه. |
| **نقل شجرة العمل…** | ينقل المجلد ويحدّث روابط git في الاتجاهين. غير متاح وهي مقفلة أو مفتوحة في علامة تبويب: تُحفظ علامات التبويب وتخطيطها حسب المسار، فتبقى علامة التبويب مشيرة إلى لا شيء. أغلقها أولًا. التراجع يعيدها إلى مكانها. |
| **إزالة شجرة العمل** | يسأل git أولًا عمّا سيُفقد. الشجرة النظيفة تحصل على التأكيد المعتاد، والتراجع يعيد إنشاءها على الفرع نفسه في المجلد نفسه. والتي بها تغييرات غير مُودعة تحصل على تأكيد منفصل، *تجاهل وإزالة*، يذكر عدد الملفات، دون تراجع. |
| **إعادة ربط المجلد المنقول…** | فقط في صف *مفقودة*: حدّد أين ذهب المجلد (نقلته بمدير الملفات) فيعيد git ربطه عبر `git worktree repair`. |
| **نسيان شجرات العمل المفقودة** | وهو أيضًا زر الممحاة في ترويسة القسم، ويظهر حين يكون أحد الصفوف مفقودًا. يشغّل `git worktree prune`. |

ما **لا** تفعله هذه الإجراءات:

- **إزالة شجرة عمل تحذف ملفاتها المتجاهَلة أيضًا** — `.env` و`node_modules` ومخرجات البناء. لا يعدّها git تغييرات، لذا ينبّه إليها حتى التأكيد "النظيف"، ولا يعيدها التراجع.
- **النسيان يحذف سجل git فقط.** لا توجد ملفات لحذفها — فالمجلد اختفى — وتُتخطّى شجرات العمل المقفلة، لأن الشجرة المقفلة على قرص منفصل تبدو تمامًا كالمحذوفة.
- القفل اتفاق بين عملاء git وليس حماية للملفات: لا يمنع أي شيء خارج git من حذف المجلد.
- لا يمكن قفل شجرة العمل الرئيسية — المستودع نفسه — ولا نقلها ولا إزالتها.
- إزالة شجرة العمل لا تحذف فرعها أبدًا. احذفه من قائمة الفروع إن انتهيت منه.

## الوحدات الفرعية

أضِف الوحدات الفرعية وحدّثها (تهيئة وسحب) وزامن عناوينها واحذفها، مع حالة حيّة
لكل واحدة:

| الحالة | ما تعنيه |
|---|---|
| **متزامنة** | مسحوبة عند الالتزام الذي يسجّله الأب |
| **معدَّلة** | مسحوبة عند موضع آخر، أو متسخة |
| **غير مهيّأة** | مسجَّلة، لكنها لم تُسحب قط |
