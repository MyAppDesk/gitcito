# קומיטים

## סגנונות הודעה

בחרו אחד בהגדרות; המלחין מתאים את עצמו אליו.

| סגנון | איך זה נראה |
|---|---|
| **Conventional** | `feat(api)!: add rate limiting` — עם רשימת סוגים נפתחת |
| **Gitmoji** | `✨ add rate limiting` — עם בורר אמוג׳י |
| **Gitmoji + Conventional** | `✨ feat(api): add rate limiting` — בורר אמוג׳י *וגם* רשימת סוגים |
| **כרטיס** | `ABC-123: add rate limiting` — נזרע משם הענף |
| **רגיל** · **אוטומטי** | מה שתקלידו; במצב אוטומטי ה־AI מחליט על הצורה |
| **איש מערות** · **הייקו** | בדיוק מה שזה נשמע |

![המלחין ממולא מראש מתוך תבנית קומיט](../../screenshots/commit-template.webp)

### Gitmoji

[Gitmoji](https://gitmoji.dev) מציב אמוג׳י לפני הנושא כדי שאפשר יהיה לקרוא את
ההיסטוריה במבט אחד: 🐛 תיקונים, ✨ פיצ׳רים, 🔥 הסרות. בשני סגנונות ה-gitmoji,
כפתור האמוג׳י נמצא ממש ליד שדה הנושא. הוא פותח את **כל 75 ה-gitmoji הרשמיים**,
עם חיפוש לפי האמוג׳י, לפי `:קוד:` (מה שמשתמשי gitmoji-cli מקלידים) או לפי
המשמעות בשפה שלכם.

**Gitmoji + Conventional** שומר על הסוג והאמוג׳י מתואמים. בחרו סוג והאמוג׳י שלו
יבוא אחריו; שנו את הסוג והאמוג׳י ישתנה איתו — אלא אם בחרתם את האמוג׳י בעצמכם
(🚑️ על `fix`, למשל). אמוג׳י כזה לעולם לא נדרס.

| סוג | Emoji | סוג | Emoji |
|---|---|---|---|
| `feat` | ✨ | `test` | ✅ |
| `fix` | 🐛 | `build` | 📦️ |
| `docs` | 📝 | `ci` | 👷 |
| `style` | 🎨 | `chore` | 🔧 |
| `refactor` | ♻️ | `revert` | ⏪️ |
| `perf` | ⚡️ | | |

הבינה המלאכותית כותבת באותה צורה. אם מודל שוכח את האמוג׳י או עונה עם
`:shortcode:`, הנושא מתוקן לפני שהוא מגיע לשדה.

קומיטים שכלים אחרים כתבו כ-`:sparkles: add login` **מוצגים** כ-`✨ add login`
בגרף, בפרטי הקומיט ובתצוגות ההיסטוריה.

מגבלות:

- הבורר תמיד כותב את האמוג׳י ב-**unicode**, אף פעם לא `:shortcode:`.
- ה-shortcodes מומרים רק לתצוגה. הקומיט עצמו לא נכתב מחדש, והחיפוש בהיסטוריה
  מתאים לטקסט כפי שנכתב בקומיט.
- רק gitmoji נחשבים: נושא שמתחיל באמוג׳י אחר נשאר כמו שהוא.
- מאגר שה-hook `commit-msg` שלו מריץ commitlint עם ה-preset הסטנדרטי של
  Conventional דוחה אמוג׳י בהתחלה. זה הכלל של ה-hook, לא של Gitcito: הגדירו את
  commitlint ל-gitmoji או השתמשו שם ב-Conventional נקי.

## דברים שהמלחין עושה בשבילכם

- <kbd>↑</kbd> <kbd>↓</kbd> מעלים את **ההודעות האחרונות** שלכם.
- **בורר שותפים לכתיבה** מוסיף שורות `Co-authored-by:` מתוך רשימת התורמים של
  המאגר עצמו.
- `commit.template` / `.gitmessage` **ממלאים מראש** את ההודעה, בלי שורות ההערה.
- במהלך מיזוג, צ׳רי־פיק או ריוורט, ההודעה **ממולאת מראש** כמו ש־git היה עושה.
- טיוטות **נשמרות** לכל מאגר בנפרד, ולכן מעבר בין לשוניות לעולם אינו מאבד הודעה.

## הלינטר

בדיקה חיה ולא חוסמת: אורך הכותרת (עם מונה תווים), נקודה בסוף, כותרת שאינה בציווי
או שמתחילה באות קטנה, שורות גוף רחבות מדי. רמזים, אף פעם לא שער — הוא לא יעצור
אתכם מלבצע קומיט.

## תיקון (amend)

תיקון כותב מחדש את הקומיט האחרון עם מה שנמצא בסטייג׳. Gitcito מראה לכם קודם את
ההודעה הקיימת, כך שאתם עורכים ולא מקלידים מחדש.

**תיקון הקומיט…** על שורה בגרף עושה את אותו הדבר ל-HEAD: הוא טוען את ההודעה
המלאה, מעביר את המלחין למצב תיקון, וממקד אותו. HEAD שכבר נדחף עדיין אפשר
לתקן, אבל Gitcito מזהיר שעדכון הרימוט ידרוש דחיפה כפויה.

**ביטול הקומיט…** הוא האח ל-HEAD שטרם נדחף: איפוס mixed אל ההורה, שינויי עץ
העבודה נשמרים, וההודעה חוזרת אל המלחין. לקומיט הראשון יש מסלול ייעודי שמשאיר
ענף שטרם נולד במקום להשמיד את הקבצים.
